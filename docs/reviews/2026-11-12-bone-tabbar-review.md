## 3. 各項問題與重現

### B-01｜高：T 分類與 POI／Z 依據混在一起

**重現：** 檢查 → 骨密度 DXA → 報告分類。`low` 顯示「骨量較低（T −1.0 ～ −2.5）」，選後帶入 12 個月，`src` 指向 ESHRE POI。頁面另一處又要求停經前以 Z 值判讀，卻沒有 Z 分類可選。`T=-2.5` 同時落在目前兩個標籤的文字邊界。

**原文核對：** ESHRE 完整指引 VI.1、印刷頁 103–104 與註腳 6，在相關敘述以 Z≤−2 定義 low bone mass；建議 69 是對 POI 且低 BMD／骨質疏鬆的族群給 1–3 年。ISCD 停經前報告優先採 Z，與停經後 WHO／T 的分類分開 [S1–S3]。12 個月是該建議區間的下限，本身沒有算錯；錯在把不同定義及適用族群接成同一條規則。

**影響：** 不能以「low 和 op 都是 12 個月」宣告分類不影響日期；使用者還可能改選 `normHT` 的 60 個月或 `norm`。`docs/exam-intervals.md:82` 已承認問題，但「待確認」不是足以消除介面誤選的保護。

**建議：** 將分類依據與排程條件分開。停經前提供「Z ≤ −2.0（低於同齡預期）」及「Z > −2.0（在同齡預期範圍內）」；沒有 Z 就提供「未分類：報告未提供 Z 值」。只有符合 POI 建議的狀態才帶 12 個月。停經後若保留 T 分類，明寫 `−2.5 < T < −1.0`、`T ≤ −2.5`、`T ≥ −1.0`（邊界另以 IOF 官方診斷表交叉核對 [S8]），不要沿用 POI 的 `src` 當一般停經後追蹤指引。可直接採用第 4.1 節的標籤及 `src` 草案。

這是報告建議，不在本次修改程式。舊 `preset:'low'` 的語意原本是 T 分類，日後不能只改同一 key 的顯示文字，就把歷史紀錄變成已確認 Z≤−2；應保留舊值讀取與原語意，新增可區分的 key 或分類依據欄位。

### B-02｜高：HT 條件被簡化，5 年提醒被包裝成固定追蹤間隔

**重現：** 選「正常，且規律使用荷爾蒙治療」，立即帶入 60 個月。`src` 和頁內依據只寫「規律」，未標出全身性且足量；依據表的「預設」顯示「5 年」。

**原文核對：** 建議 68 的前提包括 BMD 正常，以及已開始並持續足量全身性 HT。其結論是 5 年內重測價值低，並非指定滿 5 年必須檢查 [S1–S2]。例如僅局部陰道雌激素不能僅因規律使用就套此分支。`docs/exam-intervals.md:76` 前半有正確限定，後半卻寫成「5 年內不必重測」，比原文更強；工具轉成 60 個月的解釋也沒有出現在實際選項旁。

**建議標籤：**「POI：BMD 正常，且持續足量全身性荷爾蒙治療」。

**建議 `src`：**「ESHRE 2024 POI 建議 68：符合上述條件時，5 年內重測價值低。60 個月是本工具的再評估提醒，不是指引規定滿 5 年重測；有新增風險或醫師安排時另訂。」

若資料模型仍將 `nextDue` 一律呈現為「下次檢查」，較清楚的最小做法是讓醫師明訂日期／間隔，再保存其選擇；不要用來源文字聲稱 60 個月就是指引的固定追蹤值。不能把此處當作「區間取下限」：建議 68 沒有給一個重測區間。

### B-03｜高：沒有適用條件的 12 個月 fallback

**重現 A（全新紀錄）：** 新增骨密度，保留「未分類」，不用任何 T／Z 或 POI 資訊，就會自動帶入並可保存 `interval:12`。分類未知不等於已確認低 BMD。

**重現 B（舊資料／匯入）：** 用合成紀錄：

```js
{ exam:'bone_dxa', date:'2025-11-25', preset:'norm',
  interval:null, nextDue:null, labs:{}, createdAt:1 }
```

不需要 `cat`。在合成今天 `2026-10-30`，檢查卡顯示「正常（未使用荷爾蒙治療）」且「間隔 1 年」，到期日 `2026-11-25`；首頁寫「26 天後到期」，摘要也列出該日。開啟編輯時間隔卻是空的，直接存檔被擋，要求填間隔或指定日期。顯示與編輯使用了兩套語意。

**原因：** `EXINFO` 只攜帶 `noFollow`，沒有 `ask`；`dueWith` 不能區分「不排」、「尚待醫囑決定」與「用固定間隔」。`norm` 被正確排除於 noFollow，卻因此落到 `def:12`。現有測試第 72 行及提醒參考測試明確鎖定這個 fallback。

**建議：** 新的未分類／沒有 Z／待確認狀態，以及舊 `norm` 缺乏計畫時，顯示「追蹤計畫待確認」，不要自造 12 個月。仍在首頁、檢查清單、摘要與排程列出待處理項目，不能改成 `noFollow` 後靜默消失。已有合法 `interval` 或 `nextDue` 的舊紀錄照原計畫讀取；另存原始資料，不在讀取時覆寫。若固定間隔是醫師明確設定，應讓使用者確認採用並標示來源，不要默認所有缺值都是醫囑。

**界線：** 本反例目前仍會提醒，並非「null 造成漏提醒」。列高是因未具適用條件的臨床預設／來源；真正的無效日期漏提醒見 B-04。新增 `ask` 的狀態語意時，頁面、摘要和 evening／weekly 的算法必須一起更新。

### B-04｜高：手填間隔繞過範圍／整數驗證，可造成無效日期漏提醒

**位置與歸因：** `recForm` 原有 `novalidate`，`fInterval` 雖有 `min=0 max=240 step=1`，submit 只檢查是否空白。這是從基底沿用的共用缺口；新增必須自己填間隔的 `norm` 直接暴露它，故列入本次範圍。

**重現（實際 fill 與 click，不呼叫 submit handler 或改 disabled）：** 新增 DXA，檢查日填合成的 `2026-10-01`，選 `norm`，指定日期留白，填下列間隔後按儲存：

| 輸入 | 瀏覽器欄位 `validity.valid` | 實際結果 |
|---|---|---|
| 空白 | true | 被業務驗證擋下，零新增；焦點回間隔欄 |
| `0` | true | 存入 0；顯示待安排，仍提醒，沒有靜默漏追蹤 |
| `-1` | false | 存入 −1；下次日期早於檢查日，為 `2026-09-01` |
| `1.5` | false | 存入 1.5，但日期算法只得到 `2026-11-01`，與「1.5 個月後」文字不一致 |
| `241` | false | 超過 HTML 最大值仍可存入 |
| `1000000000000` | false | 存入數字；預覽 `NaN/NaN/NaN`，計算結果 `NaN-NaN-NaN` |

最後一筆 `nextDue` 實際仍是 null；無效的是 `dueOf` 計算結果，並非聲稱 DB 的 `nextDue` 被寫成字串 NaN。以原 `date helpers`／`med helpers` 再核對：`dnum(due)` 為 NaN，首頁 `dd<=60` 為 false；摘要的兩個日期比較亦為 false，因此「待處理」和「之後 180 天內到期」都顯示沒有。檢查頁可能仍呈現 NaN 日期，不能取代提醒。另以 `dev/remind-ref.js` 和假資料執行晚上提醒：null 會列固定間隔日期、0 會列待安排，但極大數案例的提醒文字不再含骨密度；這只是排程參考實作的結果，未呼叫正式任務。

**建議：** 在預覽與 submit 共用驗證：非空間隔必須有限、整數、落在允許範圍；`ask` 若要求定期追蹤，明確決定是否允許 0 作「計畫待安排」。驗證 `addMonths` 結果是合法日期，失敗不寫。即使有指定日期，也不要順便存下非法間隔。匯入／舊資料的無效值應保留可修復原文並顯示「日期待確認」，不讓它進正常到期排序後消失。無效時將錯誤關聯到欄位、保持草稿，不只發 toast。

這裡不要求把 `labs` 改數值型別；間隔是排程運算值，與應保持文字的 T／Z 檢驗欄位不同。

### B-05｜中：補登後「今天」需要多按一次

**重現：** 合成今天 10/30 → 更多選 10/20 補登 → 體重分頁 → 按「今天」。頁面仍顯示 10/20 補登；再按「今天」才回到 10/30。頁面上方「‹ 今天」亦只 `go('today')`，不重設日期。

**原因：** 重設日期的條件含 `cur==='today'`。這不是測試漏掉的偶發退步：`dev/tabbar-test.js:90–93` 明確驗證並接受此設計。

**建議：** 將使用者明確按「今天」解釋為回到 `logicalToday()`，無論原來在哪一頁；瀏覽器返回若要保留補登情境，可維持另一套導航語意。若產品決定保留原行為，應改成「紀錄」等符合語意的標籤，並讓補登日期清楚可見。本項為操作設計建議，不宣稱系統暗中把顯示為今天的數據存到昨天；目前畫面確有補登標示，但回到真正今天多一次點擊。

### B-06｜中：底部導覽的鍵盤焦點路徑未一起調整

**重現：** 用 Tab 聚焦「體重」，Enter 啟用。`cur='weight'`，畫面捲到頂，但焦點仍在 DOM 末端的體重按鈕。再 Tab 到檢查、用藥、更多；沒有直接進新內容的捷徑。另從更多選設定，dialog 關閉後焦點回到「更多」；下一次 Tab 已離開文件內最後一個控制項（Chromium 中 `activeElement` 為 body），沒有進設定表單。

**判定：** 不是焦點被永久困住，也不能僅因焦點留在導覽就判定違反 WCAG。問題是底部位置、DOM 順序及本工具「進頁就操作」的使用方式合在一起，造成不方便進入新內容；沒有實測螢幕閱讀器，故不宣稱它一定漏讀。W3C 的 SPA 導覽範例允許留焦點或移焦點兩種策略，但要求考慮進入內容的效率 [S5]。

**建議：** 由鍵盤啟動頁面切換後，聚焦對應標題或內容起點（例如 `tabindex=-1`），或提供明確的「前往內容」路徑；更多面板關閉後亦相同。保留觸控時自然的導覽體驗。不要僅為五個按鈕改套 `role=tablist` 而不實作完整 tab 鍵盤模式；現在的 nav＋button＋`aria-current` 可以成立。

### B-07｜中：「更多」未參與返回狀態處理

**重現：** 今天 → 體重 → 檢查 → 瀏覽器返回，正常回體重且標示同步。此時打開更多，再用瀏覽器返回：hash 回到今天、`cur='today'`、今天分頁被標示，但 `moreSheet.open===true`，面板仍遮住新頁。Esc 或點背景可以關閉。

**原因：** 開面板沒有新增可返回狀態；`hashchange` 只呼叫 `show`，也不關閉這個無草稿的導覽面板。這沿用原更多面板的生命週期，不是底部分頁列才首次出現的機制。

**建議：** 至少在 hash 導覽發生時關閉 `moreSheet`，使實際可見畫面與分頁標示一致；若要求返回先只關面板，再統一設計 history 狀態。不要一律關閉所有 dialog，以免誤丟尚未存檔的檢查草稿。增加 `goBack()` 斷言，原測試只有點背景與程式關閉，無法覆蓋此情境。Android 系統返回及 iOS 手勢返回仍須真機驗證。

### B-08｜低：指示線與內容截斷邊緣重疊的視覺問題成立，但不是整條線飛出 nav

**重現：** 執行 `node dev/tabbar-test.js`，檢視 `dev/screenshots/380x667-dark-tabbar-today.png`。今天的白色短線貼著被分頁列截斷的飲食文字，看起來像畫在後面的卡片上。

**量測：** 380×667 中 nav 的上緣是 y=608；button 上緣 y=609；`::before` 是 `top:-1px;height:3px`，所以線起點 y=608。它確實高於按鈕上緣 1px，覆蓋 nav 的邊框；**本次沒有量到它超出整個 nav 外框上緣**。因此應修正視覺干擾，但不把「整條線凸到 nav 之外」當成已證實幾何事實。

**建議：** 將線內縮，例如 `top:3px` 或 `4px`，並保留足夠圖示上方空間；也可改成按鈕內的底線／背景標記。必要時裁切 nav 裝飾溢出，但先確認不裁掉 focus ring。不要增加 z-index，這無法解決貼著截斷文字的問題。補上捲動前後的深淺色人工視覺驗收；現在只檢查線高 ≥2px，抓不到此問題。

## 4. 指定問題的核對結論與設計建議

### 4.1 停經前、報告只提供 T 值：分類與排程分開

本節是產品設計情境，不是個案診斷。僅有月經週期較長的資訊，不能自動認定 POI、已停經或可套 WHO 分類；POI 的確認還有年齡、病史及生化條件 [S1]。在未確認適用性前，不自動套 ESHRE 的 12／60 個月。

建議用兩層簡單選擇：先決定「以 Z 判讀／以 T 判讀／尚待確認」，再決定追蹤計畫。不必新增一大套風險評分。

| 情境 | 建議標籤 | 間隔與建議 `src` |
|---|---|---|
| 停經前，有適當 Z 報告且低於界線 | **Z ≤ −2.0（低於同齡預期）** | 分類來源：ISCD 2023。只有已確認 POI 且適用低 BMD 建議時帶 **12 月**；`src`：「ESHRE 2024 POI 建議 69：低 BMD／骨質疏鬆依風險 1–3 年，本工具取下限 12 個月；非 POI 依醫囑。」 |
| 停經前，Z 高於界線 | **Z > −2.0（在同齡預期範圍內）** | 分類本身不提供固定間隔，不直接命名為「正常／無風險」。若符合 B-02 的完整條件，才提供經明確標示的再評估提醒；其餘自行填計畫。 |
| 停經前，只有 T 值，或判讀資料不足 | **未分類：報告未提供 Z 值（T 值僅記錄）** | 不推定 Z、不選 `low/op/normHT`。`src`：「ISCD 2023：停經前優先用 Z；現有資料不足以依 Z 分類。請補報告或依醫師評估指定追蹤日期。」沒有可從該來源取出的數值下限。 |
| 停經後；或醫師確認可採 WHO 的過渡期情境 | **T ≥ −1.0（WHO 正常骨量）**、**−2.5 < T < −1.0（WHO 低骨量）**、**T ≤ −2.5（符合骨密度骨質疏鬆門檻）** | 分類來源：ISCD 2023／WHO 適用情境。`src`：「此為分類依據，非固定重測間隔。ISCD 2023 要求依個別臨床條件決定；請填醫師指定間隔或日期。」若要增加一般停經後的自動間隔，應另查適用指引，不能搬 POI 的 1–3 年。 |
| 已由醫師判定骨質疏鬆，分類不能單靠本表處理 | **醫師已判定骨質疏鬆（依報告）** | 保留診斷文字及醫囑；適用 POI 時可明確引用建議 69，其餘依其治療／風險方案，不從 T/Z 數值自動推斷。 |

「依指引區間取下限」適用於明確的 **1–3 年 → 12 月**，不適用於「個別決定」或「5 年內重測價值低」。來源沒有固定間隔時，工具也不應自己補一個數字。

只有 T 的報告仍可原樣保存：把 T 填進對應 T 欄，BMD 若有也保存，Z 留白。向檢查單位要求適用參考資料庫的 Z 值／補充判讀；**不能從 T 單獨換算 Z，也不能把 T 複製進 Z 欄**。等待期間可手動填已確認的追蹤計畫；未定計畫時應保持可見的「待確認」，而非空到期日且無提醒。

現有 11 欄只有腰椎 Z，沒有股骨頸／全髖 Z。這符合本次列出的 11 欄需求，不另算漏做；但若日後實作上述 Z 分類，不能把「腰椎 Z 在同齡範圍內」直接推成所有部位正常。可從完整報告人工選分類，或新增髖部 Z 欄位；新增 key 保留舊 labs，不把缺值補 0。歷史 T 分類須可辨識為舊分類，不能靜默重貼 Z 標籤。

頁內短說明建議改為：「停經前優先以 Z 值判讀；只有 T 值可先記錄，不自動分類。停經後採 T／WHO；更年期過渡期是否採用由醫師判定。分類與追蹤間隔各有適用條件。」這比目前絕對化的「不用 T」更貼近 ISCD 的 preferred 用語，也避免否定特殊臨床情境。

### 4.2 `norm` 能不能存成不提醒？舊資料如何編輯？

- **一般空白不能繞過：** interval 與 nextDue 都空時，按儲存被擋下；沒有發現只換分類／關閉再開就把兩個空值存成新紀錄的正常路徑。
- **0 可以存，但不漏提醒：** 它表示「待安排」，`dueWith` 回檢查日，首頁及摘要明確列待安排。這是否符合 `norm` 產品語意可再決定，不能把它報成無到期日而靜默消失。
- **合法指定日期可以取代間隔：** `interval:null,nextDue:有效日期` 是有效計畫，不是缺到期日。
- **真正漏洞是 B-04 的無效非空值。** HTML 屬性無法在 `novalidate` 下代替業務驗證。
- **舊 `norm` 有間隔：** 編輯保留該值，不因 `ask` 自動清掉；24 個月可原樣保存。已選好的指定日期也保留。重新選 preset 會清空間隔，但不清除指定日期，後者依既有優先序生效。
- **舊 `norm` 兩者皆空：** 閱讀時套 12 個月、編輯時仍空、再存被擋，是 B-03。不要用自動填 12「修復」以掩蓋缺計畫狀態。

### 4.4 T、Z 負值：目前沒有把負號吃掉，文字模型也不是錯誤

6 個 T／Z 欄位是預設 type=text，沒有 `inputmode=decimal`，並關閉 autocapitalize、autocorrect、spellcheck；5 個 BMD 欄位保留 decimal 提示。這避免程式明確要求只有數字小數的鍵盤，但鍵盤實際樣式仍由 OS 決定，不能宣告每支 iPhone 都已驗證可直接看見負號。

`-2.0`、`−1.5` 實測均原樣存入 labs。儲存只 trim，不經 `parseFloat`，因此 Unicode 減號沒有變正數，字串儲存符合 README；不應要求改成 number 而破壞既有欄位格式。現況也沒有專門拒絕 `--2` 等不合法 score 的驗證，故不能宣稱「數值已驗證」。若將來做自動分類，應先保留 raw，另以完整字串驗證處理 ASCII／Unicode 負號，不能用 parseFloat 接受前綴或把缺值當 0；目前沒有自動從 labs 推分類，未重現合法負數被改寫。

### 4.5 分頁列、遮擋與真機界線

**分頁與標示：** 今天／體重／檢查／用藥切換後只有對應一顆 `aria-current='page'`。運動、飲食、摘要、設定屬更多，底部更多用 `aria-current='true'`，面板內只有對應那列為 page；從主分頁打開更多不把它誤當新頁，沒有子列被標示。Esc／背景關閉可用。頁面上方返回是「‹ 今天」，不是歷史上一頁；瀏覽器返回則循 hash 歷史，普通換頁與標示同步，更多開啟時有 B-07。

**觸控與對比：** 380 寬時每顆約 **69.6×58 CSS px**，超過專案 44×44 標準；有可見圖示及文字、focus-visible、字重與指示線，不只靠顏色。深淺色既有掃描通過。`aria-current` 用在 nav 的目前項目合理 [S4]；不能因產品叫「分頁」便要求一定使用 ARIA tabs。自動掃描是尺寸／CSS 文字對比檢查，不涵蓋完整 AT 行為、焦點效率或裝飾疊字。

**一般 viewport 遮擋：** 分頁列實測 59px 高（58px 按鈕＋1px 邊框）；main 底部 padding 146px；root scroll-padding-bottom 70px。既有測試逐頁捲到底及對控制項 `scrollIntoView({block:'nearest'})` 後命中測試通過。最後內容可以完整捲到列上方；toast 底緣高於列上緣約 11px，其撤銷可點。所有測到的 modal 儲存鈕可見、可命中；`showModal()` 的 top layer 在分頁列之上。骨密度長表單由 `.dlg-body` 自己捲動，root 的 scroll-padding 不等於該內層 scroller 的 padding，所幸其 footer 本身佔 layout 空間。

**safe-area：未驗證真機。** 程式把 bottom inset 加在分頁列和 toast，也放進 root scroll-padding；main 的 146px 沒有直接加 inset，只有固定預留。不能因測試環境 inset=0 就宣稱已測非零安全區。建議把 main 預留也由同一個「列高＋inset＋內容間距」公式計算，降低未來改列高後不同步的風險；目前不據此宣稱已發生最後卡片永久遮住。

**鍵盤浮動：未驗證真機。** 沒有 VisualViewport 鍵盤處理或編輯時隱藏底列的邏輯。OS 鍵盤會牽涉 visual viewport 與 layout viewport，不能用單純縮短 Playwright viewport 模擬等同；safe-area 也不是鍵盤高度 [S6–S7]。一般頁（設定表單）存在底列停在可視區下緣、占用輸入區的可能；modal 則不會被底列蓋住，但仍可能被 OS 鍵盤蓋住。這些是需驗收的條件，不是本次已證實的 iOS bug。

建議用目標 iPhone／Artifact 容器逐一驗證：設定最後幾個輸入欄、骨密度最下方 labs／note、鍵盤開啟時存檔與 toast、上下捲動、收鍵盤、直橫轉。紀錄 OS／容器版本與 visual viewport 實際高度。若實測底列隨鍵盤浮起，輸入期間暫藏非必要導覽並同步還原 padding 是簡單選項；若依 VisualViewport 判定，須排除縮放／旋轉，不能只以任何高度縮小就認定鍵盤。

## 5. 建議修正及驗收順序

先修 B-04 的間隔有效性，保證不存無法排程的值；同時處理 B-01–B-03，讓標籤、適用條件、來源、未定計畫及舊資料語意一致。之後統一今天／補登導航、更多返回與鍵盤焦點，將指示線收進列內。

回歸至少包含：

1. 停經前只有 T 不被自動歸入 Z 分類；Z 的 −2.0 邊界；T 的 −1.0／−2.5 邊界；POI 適用性與足量全身性 HT 不足時不能自動帶 60 個月。
2. norm 的空白、0、負數、小數、超界、極大數、指定日期及編輯舊紀錄；無效值零寫入；缺計畫必須在首頁／摘要／排程保持可見。
3. 缺 cat、舊 preset、未知 labs key、舊備份與新備份往返；不改已存在的醫師指定間隔。
4. 若擴充 DXA 截圖支援，以合成 DXA 本身測試日期、側別、部位、負號、未提供 Z、原文保留及分類確認，不能繼續只用 TSH 改選來代表。
5. 真實瀏覽器 back、Esc、鍵盤 Enter／Tab、更多選項返回後焦點；今天的一致行為；深色捲動時指示線；對話框／toast 同時存在。
6. 以真機補上第 4.5 節；把「未驗證」逐項改成有版本和證據的結果。正式排程同步屬發布工作，另依既有部署流程執行，本審查不代做。

- **[S2] ESHRE／ASRM／CRE WHiRL／IMS，2024 最終版 POI 完整指引。** [官方指引頁](https://www.eshre.eu/Guidelines-and-Legal/Guidelines/Premature-ovarian-insufficiency)；[完整 PDF](https://www.eshre.eu/-/media/sitecore-files/Guidelines/POI/2024/INTERNATIONAL-GUIDELINE-ON-POI-2024.pdf)。核對印刷頁 17 建議 68／69、VI.1 印刷頁 103–104／註腳 6–7，以及 VI.3 監測章節。完整指引也討論特定年輕慢性病情境的 T 值用途；因此本報告不把 ISCD 的「優先用 Z」擴張成所有情境禁止參考 T。
- **[S3] ISCD 2023 Adult Official Positions。** [官方全文](https://iscd.org/official-positions-2023/)。核對 BMD Reporting（停經前／後）、Central DXA for Diagnosis、Follow-Up BMD Measurements、跨儀器比較及報告要求。Z 分類不是固定追蹤間隔；同機 BMD 比較是有用的簡寫，但判定有意義的變化仍需 precision／LSC，經適當交叉校正的設備也不能一概說無法比較。
- **[S4] W3C WAI-ARIA 1.2。** [aria-current](https://www.w3.org/TR/wai-aria-1.2/#aria-current)。目前頁／目前項目的語意；不因 nav 稱作分頁就強制使用 tablist。
- **[S5] W3C APG，Navigation Treeview Example。** [Focus Movement After Content Load](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/examples/treeview-navigation/)。本報告僅借用其 SPA 換內容後焦點策略的說明，沒有要求此工具改成 treeview，也不把可選焦點策略誤當規範強制條文。
- **[S6] CSSOM View。** [VisualViewport](https://drafts.csswg.org/cssom-view/#visualViewport)。區分 layout／visual viewport，用於說明為何一般 headless viewport 不等於 OS 鍵盤實測。
- **[S7] WebKit Bug 217754。** [Safe-area-inset-bottom still set when keyboard appears](https://bugs.webkit.org/show_bug.cgi?id=217754)。僅作平台上 safe-area／鍵盤交互作用的風險依據，不能推導本工具在每個 Safari／WKWebView 版本必然重現。
- **[S8] International Osteoporosis Foundation。** [Diagnosis](https://www.osteoporosis.foundation/health-professionals/diagnosis)，Diagnostic criteria 表。交叉核對正常包括 −1.0、骨質疏鬆包括 −2.5；用途是避免選項邊界重疊，不作重測間隔來源。
