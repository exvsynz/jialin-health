2026-10-30。對應 `2026-10-30-phase-A-code-review-gpt.md`。修正在 `ccr-9364f60a-xq6vfj` 的 B2、B3 兩個提交，規格同步更新。

| # | 嚴重度 | 處理 | 說明 |
|---|---|---|---|
| 1 | 高 | 部分處理，其餘交給平台實測 | 審查說得對：提示詞保證不了平台不推播。改成只用一個通知管道：<br>- 有推播工具時由工具送出，排程任務關閉完成通知（規格 7 的 A 設定）。<br>- 沒有推播工具時才靠平台的完成通知（B 設定），而且必須實測無缺、暫停、關閉、太晚、重複五種情況都不推播。<br>最終回覆仍保留一行固定文字，因為回覆一定會有內容；A 設定下它不會變成通知。 |
| 2 | 中 | 已修 | `pushed` 改成 `shouldPush` 加 `delivery`（`tool_sent`／`tool_not_sent`／`tool_error`／`platform`／`none`）。<br>先交付、再寫心跳，記錄的是交付結果。規格寫明 `delivery` 不代表手機收到。 |
| 3 | 中 | 已修 | 心跳讀取失敗會重試一次；還是失敗就不寫心跳、不做重複檢查，週報寫「排程讀不到」。<br>寫入時，任何失敗（包括別人搶先建立）都會重讀、重新合併、再寫一次；還是失敗就放棄。測試替身逐項驗證。 |
| 4 | 中 | 已修 | 新增執行識別碼 `run`。合併時依 `run` 去重、依 `at` 排序，頂層取最新那筆。<br>同一天同一種檢查已經送出（`tool_sent` 或 `platform`）就記 `duplicate`，不再推播。<br>兩個工作階段幾乎同時執行、都還沒寫入心跳時，仍可能各推一次；這需要平台提供鎖，`if_version` 做不到。 |
| 5 | 中 | 已修 | 心跳時間的毫秒數字要能轉成有效的日期；ISO 字串要帶 `Z` 或時差。`renderHb` 另加保護。<br>測試涵蓋 `1e20`、沒有時區的字串，以及今天頁在這些情況下照常重繪。 |
| 6 | 中 | 已修 | 讀到心跳就先整理 `recent`：不是陣列當成空的、過濾無效項、只保留白名單欄位。週報計數和寫回都用整理後的結果。 |
| 7 | 中 | 已修 | 每個開關有操作序號，只有最後一次點擊決定開關狀態與 toast；撤銷走同一條路徑。<br>測試涵蓋慢網路下的連續切換、第一筆失敗、撤銷。mock 在第一筆的快照送出前就已套用後面的寫入，所以「反跳」本身重現不出來；舊程式在這組測試失敗的是過時的 toast。 |
| 8 | 中 | 已修 | 到期日和頁面 `dueOf` 完全一致：`interval` 不是數字時，用 `settings/intervals` 或預設間隔；「不追蹤」的分類不列入。<br>提示詞的檢查表加上預設間隔與「不追蹤」清單，測試和頁面比對；參考實作和頁面比對 11 筆紀錄。 |
| 9 | 中 | 部分處理 | 送出前再看一次時間，邏輯日變了或超出時段就記 `late`。<br>跨日延遲：排程任務沒有提供預定的執行時間，所以偵測不到。規格寫明這個限制：延遲的執行檢查的是當下這一天的資料，內容仍然正確。 |
| 10 | 中 | 已修 | 流程改成先讀 profile 與心跳。已知暫停、關閉、太晚就不讀其他文件，所以不會因為讀取錯誤而推播。<br>只有 profile 本身讀不到時才推讀取失敗，因為那時無從知道使用者是否關閉了提醒。 |
| 11 | 中 | 推播已改，頁面待決定 | 推播裡 `interval` 0 從「需盡快處理」改成「待安排」，不寫急迫程度。<br>頁面本身仍把 `interval` 0 顯示成「需盡快處理」（表單說明、今天頁到期卡、檢查頁）。這是 A 階段以前就有的，屬於臨床文字，這次沒有改，留給使用者決定。<br>審查引用的 Lung-RADS v2022 Category 0 原文，這次沒有另外查證。 |
| 12 | 低 | 已修 | 今天頁只在確定超過 26 小時時出現；時間無法辨識只在設定頁警示。 |

**測試缺口**

| 位置 | 處理 |
|---|---|
| 同時寫入、payload | mock 寫入紀錄加上 payload。新增：<br>- 交錯寫入（兩個開關加「儲存設定」）<br>- 既有其他 key 不變<br>- 首次建立 profile 文件<br>- 寫入中收到遠端快照 |
| 版本條件、ArtifactData 替身 | 新增 `dev/fake-artifact-data.js`。參考實作照提示詞步驟對它實際執行，涵蓋：<br>- 寫入衝突、建立競爭、連續衝突、非衝突的失敗<br>- 推播工具成功、未送出、出錯<br>- 分頁 |
| 實際執行提示詞 | 這個環境無法啟動排程任務來執行提示詞，所以沒有處理。改為規格第 7 節的平台實測（六種情況）。prompt-test 的檔頭也寫明它只檢查文字。 |
| 表單重繪、假時鐘 | 改成輸入新值並保持焦點，跨過每分鐘重算後檢查值與焦點；新心跳的時間取頁面的假時鐘。 |
| falsy 與 null 不一致 | 提示詞改成和頁面相同的「沒有值」（不存在、`null`、`false`、`0`、空字串），並測試這四種值。 |
