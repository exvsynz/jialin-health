# D 階段規格：從截圖填入檢查紀錄

2026-11-01 擬定。狀態：2026-11-01 使用者確認第 10 節 D1–D4 全部照建議，實作中。

範圍：「新增檢查紀錄」面板加「從截圖填入」。
- 選 1 張或多張截圖，用 `sample`（images）讀出固定格式的 JSON。
- 讀出的內容拆成一筆或多筆草稿，逐筆在現有表單裡確認後才存。
- 截圖本身不存。

`sample` 的用法與錯誤處理照 `docs/specs/phase-C.md` 第 4 節，型別以 `docs/contract/0.2.94/sample.d.ts` 為準。和 C 不同的地方會寫明。

背景：家琳的檢查結果大多在「全民健保行動快易通｜健康存摺」的「檢驗檢查結果」與「影像／病理報告」裡。這兩個畫面實際有哪些欄位、日期用民國還是西元，沒有查到官方說明（第 7 節）。所以讀取規則兩種日期都接受；檢驗名稱用對應表，之後實測再補。

## 1. 完成的定義

全部符合才算完成：

1. **入口**：新增檢查紀錄時，面板最上方有「從截圖填入」。
   - 編輯既有紀錄時不顯示。
   - 這個檢視不能送圖片給 Claude 時也不顯示，規則和「拍一餐」相同（4.1）。
2. **讀取**：從相簿選 1 張或多張截圖，一次呼叫 `sample` 讀完。
   - 讀取中顯示「讀取中」與「停止」。
   - 讀取期間關掉面板不會中止；讀完後可以回來繼續（5.6）。
3. **讀出的內容**：檢查日期、醫院、檢查項目、檢驗數值（名稱、數值原文、單位、參考範圍）、報告文字、報告分類的原文。
4. **對應到現有欄位**：
   - 檢驗名稱對到 `thy_lab`、`gyn_horm` 的 labs 名稱，例如 FREE T4、FT4 → `Free T4`（3.4）。
   - 對不到的檢驗放進報告內容，不丟掉。
   - 單位和表單欄位不同時，標出來，不換算（3.3）。
5. **多筆**：同一次讀取可以拆成多筆草稿（例如同一天抽血有甲狀腺與生殖軸激素），逐筆在現有表單裡確認後才存。可以略過某一筆。
6. **報告分類**：
   - 只有截圖上寫出分類時才建議，例如「BI-RADS 3」。
   - 建議的分類明顯標示「由截圖判讀，請確認」，不確認就不能存。
   - 讀不出分類就留空（3.6、5.4）。
7. **重複**：已有同一天、同一項目的紀錄時，提示可能重複（3.9）。
8. **錯誤與同意視窗**：比照飲食照片。每一種錯誤碼都有對應的畫面；任何錯誤都不會寫入資料庫（4.5）。
9. **提示詞**：
   - 用繁體中文寫。
   - 只抄錄截圖上看得到的內容；看不清楚的欄位留空並標成看不清楚。
   - 不做任何臨床判斷或建議（4.4）。
10. **隱私**：
    - 截圖只留在這次開啟的頁面記憶體裡，不寫進資料庫，也不在匯出裡。
    - 頁面上一行說明「截圖會送給 Claude 讀取」並建議先裁切（第 6 節）。
11. **點擊數**：每種情境的步驟數寫在 5.7。
12. **向後相容**：
    - `records` 只新增兩個選填欄位（第 2 節）。
    - 舊資料不需要遷移；手動輸入的流程不變。
13. **測試**：
    - 新測試加進 `dev/test.sh`，全部通過。
    - 包含 380 寬淺色／深色的截圖。
    - `dev/mock-claude.js` 加上截圖情境（第 8 節）。

**不在這個階段**：
- 醫師欄位：需求沒有列，不讀。
- 依息肉數目、大小、病理推算大腸鏡分類（決定 D1）。
- 回診摘要顯示旗標與參考範圍。
- 在頁面裡裁切截圖。
- 一次讀超過 6 張（決定 D4）。

## 2. 資料欄位（只新增）

`records/{autoId}` 加兩個選填欄位，其他欄位的意義不變：

```
labMeta: { <labName>: { raw, unit, ref, flag } }   // 從截圖填入、儲存時沒改過的檢驗
shot:    { at, n, promptVer, tier }                // 這筆是從截圖填入的
```

- **`labs[name]`**：照舊是文字，存法見 3.2。
  - 例如 `"5.2"`、`"<0.01"`。
  - 單位不同時加上截圖的單位，例如 `"15.4 pmol/L"`。
- **`labMeta[name]`**：截圖上的原文。
  - `raw`：數值原文，例如 `"H 5.2"`。
  - `unit`：單位原文。
  - `ref`：參考範圍原文。
  - `flag`：旗標，`"H"`、`"L"`、`"HH"`、`"LL"`、`"A"`、`"*"` 或 `null`。
  - 沒有這個檢驗的 meta 時，視為手動輸入。
- **`shot`**：
  - `at`：讀取完成的時間。
  - `n`：截圖張數。
  - `promptVer`：提示詞版本。
  - `tier`：`modelTierApplied`。
  - 只用來標示來源，畫面不依它做判斷。
- **編輯時的規則**：
  - 某個檢驗欄位在儲存前被改過或清空，就刪掉它的 `labMeta`，因為原文已經不代表這個值。
  - 沒改的保留。這和現有表單對 `labs`、`drawCtx` 的保留規則相同：只動這個表單管的 key。
- **匯出、匯入**：
  - `records` 本來就整份匯出，以相同編號的備份覆蓋，新欄位會跟著走。
  - `importLoses` 加一項：目前的紀錄有 `labMeta` 或 `shot`、備份裡沒有時，算進「會被取代」的數目。
- **存取規則不變**：`read: admin, write: admin`。
- **寫入**：只在使用者按「儲存」時，沿用現有的 `records` 寫入（新編號 `set`）。讀取、草稿都不寫資料庫。

## 3. 讀出與對應規則（`shot helpers` 區塊，node 可直接測）

模型只抄錄原文（4.4）。日期換算、數值拆解、名稱對應、分類對應、分組，都由頁面的固定規則做，可以用 node 測。

### 3.1 日期 `parseShotDate(text)`

- 先把全形數字與符號轉成半形。
- 接受：
  - 民國年：`115/10/20`、`115-10-20`、`115.10.20`、`1151020`、`115年10月20日`。
  - 西元年：`2026/10/20`、`2026-10-20`、`20261020`。
- 民國年是 2 或 3 位數，加 1911。
- 日期不合法（例如 2 月 30 日）回 `null`。
- 回傳 `YYYY-MM-DD` 或 `null`。
- **用哪一個日期**：
  - 用 `date`（檢查或採檢日期）。
  - 沒有 `date`、只有 `reportDate` 時，用報告日期，並把日期欄標成「截圖只有報告日期，請確認檢查日期」。
- **晚於今天**的日期：照填，日期欄加提示「晚於今天」。

### 3.2 數值與旗標 `splitLabValue(raw, flag)`

- 先轉半形：`＜` → `<`、`．` → `.`。去掉前後空白。
- 前後的旗標記號拆出來：
  - `H`、`L`、`HH`、`LL`、`A`、`*`、`↑`（當作 H）、`↓`（當作 L）、`(H)`、`[L]`。
  - 模型另外回了 `flag`（截圖上旗標在獨立的一欄）時，一併採用。
  - 前後兩個旗標不一致時，`flag` 存 `null`，原文留在 `raw`。
- 剩下的部分是「比較符號＋數字」時，存成值：
  - 比較符號可以是 `<`、`>`、`≤`、`≥`、`<=`、`>=`。
  - 例如 `<0.01`、`>1000`、`5.2`。
  - 千分位逗號去掉。
- 剩下的不是數字時，整段原文存成值，不拆旗標。
  - 例如 `Negative`、`陰性`、`待報`、`1:80`、`見報告`。
- **例子**：

| 原文 | `labs` 的值 | `flag` | `raw` |
|---|---|---|---|
| `H 5.2` | `5.2` | H | `H 5.2` |
| `5.2 H` | `5.2` | H | `5.2 H` |
| `<0.01` | `<0.01` | null | `<0.01` |
| `＜0.01 L` | `<0.01` | L | `＜0.01 L` |
| `1,234` | `1234` | null | `1,234` |
| `陰性` | `陰性` | null | `陰性` |
| `5.2↑` | `5.2` | H | `5.2↑` |

- 現有的 `hasResult`（含數字才算有結果）不變。「待報」照舊不算 TSH 結果。

### 3.3 單位 `unitSame(a, b)`

- **先正規化**：
  - `µ`、`μ`、`u` 視為同一個字。
  - 不分大小寫，去掉空白。
- **下列寫法視為同一個單位**：都只是寫法不同，數值相同，不是換算：
  - μIU/mL ＝ mIU/L
  - mIU/mL ＝ IU/L
  - ng/mL ＝ μg/L
  - pg/mL ＝ ng/L
  - IU/mL ＝ kIU/L
- **和表單欄位的單位不同時**：
  - 欄位照填，值後面加上截圖的單位，例如 `Free T4` 填 `15.4 pmol/L`。
  - 欄位標成「單位和表單（ng/dL）不同，未換算」。
  - 這樣在檢查歷史的表格、用藥頁、回診摘要，都直接看得到單位，不需要改那些畫面（決定 D2）。
- **截圖沒有單位時**：照填，欄位提示「截圖沒有單位」。

### 3.4 檢驗名稱對應 `labField(name)`

- **比對方式**：
  - 先正規化：轉半形、不分大小寫、去掉空白、`-`、`_`、`.`、括號。
  - 再查下表。
  - 先用模型回的 `name`（檢驗項目）；沒有 `name` 時才用 `order`（醫令名稱）。有 `name` 但對不到時，就算對不到，不改用醫令名稱，避免名稱對不到的檢驗（例如 FT3）被醫令名稱誤對到別的欄位。（實作時修正：草稿原本寫兩個都比對。）
- **對應表**：

  - Free T3／FT3：不是 T3（總量）。
  - Free testosterone：不是總睪固酮。
  - Anti-microsomal antibody：不自動對到 Anti-TPO。歷史上這是 TPO 抗體的舊名（Mayo Clinic Laboratories 的 TPO 抗體檢驗把「Microsomal Antibodies」列為別名，2026-11-02 讀原頁），但各院的檢驗方法與結果格式（例如舊式滴度）還沒確認，所以先留在報告內容。（審查 D-14 更正：草稿原本寫「是不同的檢驗方法」。）

- **對應表只看名稱、完全相符才算**：
  - 不做模糊比對，也不讓模型決定欄位，因為對錯欄位會讓數字出現在別的檢驗下面。
  - 對不到的檢驗不會丟掉，會放進報告內容（3.7）。
  - 之後實測發現健康存摺有其他寫法，就加進這張表。

### 3.5 報告的檢查項目

- 影像、內視鏡、病理報告由模型從 7 個代號中選一個（4.4），看不出來就填 `null`。
- 頁面只接受 EXAMS 裡有、而且不是抽血類（`thy_lab`、`gyn_horm`）的代號；其他值都當作 `null`。
- `null` 的草稿：表單的檢查項目顯示「請選擇」，選了才能存。
- 選項目是辨認報告的名稱，不是臨床判斷。表單裡看得到、改得了。

### 3.6 報告分類 `classPreset(exam, classText, reportText)`

- 模型只把截圖上**寫出來的分類原文**放進 `class`，不自己判斷（4.4）。
- 頁面在 `class` 和報告全文裡，找下表的寫法：
  - 只找到**一個**分類時，建議對應的 preset。
  - 找到兩個以上不同的分類時（例如左乳 2、右乳 3），不建議，提示「截圖裡有不只一個分類（2、3），請自己選」。
  - 找不到就留空。

| 檢查 | 截圖寫的 | 建議的 preset |
|---|---|---|
| 乳房超音波、X 光、電腦斷層 | BI-RADS 1、2 | `b12` |
| 同上 | BI-RADS 3 | `b3` |
| 同上 | BI-RADS 0 | `b0` |
| 同上 | BI-RADS 4、4A、4B、4C、5 | `b45` |
| 同上 | BI-RADS 6 | 不建議（沒有對應的 preset），提示「BI-RADS 6 沒有對應的分類，請自己選」 |
| LDCT | Lung-RADS 1、2 | `l12` |
| 同上 | Lung-RADS 3 | `l3` |
| 同上 | Lung-RADS 4A | `l4a` |
| 同上 | Lung-RADS 4B、4X | `l4b` |
| 同上 | Lung-RADS 0 | `l0` |
| 甲狀腺超音波 | 同一句有獨立的「ATA」字樣，並寫 high suspicion／高度懷疑 | `high` |
| 同上 | 同上，intermediate suspicion／low suspicion、中度懷疑／低度懷疑 | `lowint` |
| 同上 | very low suspicion、極低懷疑、benign | 不建議：現有的分類還要看結節大小（≤1 cm 或 >1 cm）或穿刺結果 |
| 同上 | 同一句有否定（no、not、without、未見、無、沒有、非、不是），或講的是復發風險（recurrence、復發、風險） | 不建議：否定句與癌症復發風險系統都不是結節的超音波分類（ATA 2015 分開定義，審查 D-04） |
| 同上 | 只寫 TI-RADS（ACR、K-TIRADS 等） | 不建議：TI-RADS 不是 ATA 分類，換成 ATA 是臨床判斷 |
| 大腸鏡、胃鏡 | 任何寫法 | 不建議（決定 D1） |

- **細節**：
  - Lung-RADS 的版本號（例如「v2022」「v1.1」）不是分類，略過。
  - 「分類」指截圖寫出的原始分類，不是對到的 preset：寫了兩個不同的原始分類（例如 4A 與 4C、1 與 2），即使對到同一個 preset 也不建議（審查 D-12）。
  - S 修飾（例如「2S」）不影響對應：ACR Lung-RADS v2022 原表 note 15，S 可以加在 0–4 任一類，用來標示肺癌以外、臨床上可能重要的發現。原文留在報告內容。
  - 4X：同表 note 14，4X 是獨立的類別，X 不當修飾用（2026-11-02 讀 ACR 網站上的 Lung-RADS v2022 PDF）。照使用者既有的決定對到 `l4b`。
  - BI-RADS 4A–4C 對到 `b45`，Lung-RADS 4B 與 4X 對到 `l4b`，都沿用現有 preset 的標籤（「BI-RADS 4–5」「Lung-RADS 4B／4X」）。不新增任何間隔值，也不改現有的依據文字。
- **建議不等於存下**：建議的 preset 預先選好，但要按「確認分類」或自己改選，才能存（5.4）。

### 3.7 分成多筆 `groupShot(items, today)`

- **檢驗**：
  - 對到欄位的，依「檢查（`thy_lab` 或 `gyn_horm`）＋日期＋醫院」分組，每組一筆草稿。
  - 醫院沒有讀到時，以「未讀到」當作一個值。
- **重複的檢驗**：
  - 同一組裡同一個欄位出現兩次、數字相同、單位相同或其中一列沒有單位、旗標不衝突（截圖重疊）：只留一個，另一列才有的參考範圍、旗標、單位補進來（審查 D-06）。
  - 數字不同，或數字相同但單位不同：
    - 欄位不填，提示「截圖裡有不同的值：5.2 μIU/mL、5.3 μIU/mL」。
    - 兩列都完整寫進報告內容（名稱、數值、單位、參考範圍、旗標），不換算、不替使用者選。
- **對不到的檢驗**：
  - 放進同一天、同一家醫院的第一筆檢驗草稿，依 EXAMS 的順序（甲狀腺在前）。
  - 報告內容加一行標題「其他檢驗（沒有對應的欄位）：」，下面每個檢驗一行，例如 `FT3 3.1 pg/mL（參考值 2.0–4.4）H`。
  - 同一天、同一家醫院沒有任何對到的檢驗時，自成一筆草稿，檢查項目是「請選擇」。這種情況可以「略過」，不會被強迫存成某一種檢查。
- **報告**：每一份報告是一筆草稿。
  - 只有檢查項目、日期、醫院、標題、全文、分類原文都相同時，才當作重疊的同一份（審查 D-05）。
  - 報告內容：標題（全文沒有包含時）、模型抄的全文（最長 4000 字，超過時截斷並註明「已截斷」）、分類原文（全文沒有包含時，另起一行「截圖上的分類：…」）（審查 D-07）。
  - 沒有讀到全文時，欄位旁註明「截圖沒有讀到報告全文」。
  - 檢查項目待選的報告，使用者選了項目後才依那個項目算分類建議，同樣要確認。
  - 醫院：照填。
- **草稿的順序**：日期新的在前；同一天依 EXAMS 的順序。
- **在表單裡把檢查項目改成別的時**：原本對到的檢驗如果不屬於新的項目，存檔時寫進報告內容，不會丟掉。表單上會先提示「換成這個項目後，TSH、Free T4 會放進報告內容」。

### 3.8 去掉個資 `redact(text)`

- 提示詞要求不抄姓名、身分證號、病歷號、生日、電話、地址（4.4）。
- 頁面再擋一層：所有讀出的文字中，看起來像身分證號或居留證號的字串，改成「〔已移除〕」。
  - 一個英文字母＋9 碼數字，第 2 碼是 1、2、8、9。
  - 也擋中間有 `*` 或 `X` 遮罩的寫法，不分大小寫，全形也算（審查 D-11）。
  - 每一個讀出的文字欄位都擋（醫院、名稱、數值、單位、參考範圍、標題、分類、全文）。
- 姓名無法用規則判斷，只靠提示詞和使用者確認；所以第 6 節建議先裁切。

### 3.9 可能重複 `dupOf(exam, date, records)`

- 符合下面兩項的紀錄，就是可能重複：
  - 同一個 `exam`、同一個 `date`。
  - 在現有的 `records` 裡，包括這次剛存的草稿。
- 表單上顯示，例如：「這天已有一筆甲狀腺抽血（TSH 2.1・Free T4 1.2）。可能重複，仍要新增就按儲存。」
  - 有檢驗數值時列出前兩個，沒有就列報告的前 20 字。
- 改了日期或項目就重新判斷。
- 只提示，不擋儲存；不自動合併。

## 4. 呼叫 Claude（`sample`，contract 0.2.94）

### 4.1 用法（同 C 4.1）

- **能力檢查**：沿用 C 的 `sampleNs`、`sampleLim`、`sampleState`、`sampleOff`。
  - 「從截圖填入」和「拍一餐」同時出現、同時隱藏。
  - `limits().images` 存在、`mediaTypes` 包含 `image/jpeg`、`maxCount ≥ 1`，才顯示。
- **呼叫**：

```js
const r = await sampleNs(shotPrompt(n), { images: blobs, modelTier: "default", signal })
// 「再讀一次」多帶 cache: false
```

- 用 `sample()`，自己解析（同 C 4.1），因為要拿到 `truncated` 與 `modelTierApplied`。
- **`modelTier: "default"`**：
  - 要讀小字和表格，`"quick"` 不先思考。
  - 這是操作上的選擇，沒有測過準確度。
  - 不指定 `model`。
- **時機**：只在使用者選好截圖、或按「再讀一次」之後。不在載入時，不自動重試。
- **`signal`**：每次新建一個 `AbortController`，「停止」呼叫 `abort()`。不設逾時（同 C）。

### 4.2 圖片

- **張數**：一次最多 `min(maxCount, 6)` 張。
  - 選太多時不呼叫，提示「一次最多 6 張，請分次讀取」。
  - 6 是頁面自己的上限（決定 D4）。
- **原檔可以直接送的情況**：類型在 `mediaTypes` 裡、大小 ≤ `maxInputBytes`。
  - iOS 截圖是 PNG，通常符合。
  - 不重新壓縮，因為 JPEG 會讓小字變糊。
  - 平台送出前會縮到約 1.2 百萬像素、處理方向、去掉中繼資料（sample.d.ts）。
- **其他情況**（例如 HEIC、太大）：
  - 用 C 的解碼方式畫到 canvas，縮到 1.2 百萬像素以內，存成 JPEG。品質 0.92，太大再試 0.85、0.75。
  - 還是太大或打不開時，不呼叫，提示「第 2 張截圖打不開，請換一張」。
- **長截圖**：
  - 平台縮到 1.2 百萬像素後，很長的截圖字會變小。
  - 寬高比超過 1:3 時，讀取前提示一行「截圖很長，字可能讀不清楚，建議分段截圖」，照常讀。
  - 不在頁面裡切圖。
- **記憶體**：
  - 截圖的 Blob 只留在這次的草稿裡，給「再讀一次」用。
  - 每次讀取成功的截圖，留到這批草稿都存完、略過或丟棄為止；略過、丟棄後再等撤銷時間過了才釋放（審查 D-13）。
  - 草稿列有「重讀」：用同一批截圖、帶 `cache: false` 再問一次，取代這批還沒存的草稿；已經存過的那幾筆不再出現。
  - 不寫進資料庫，不進匯出。

### 4.3 快取（同 C 4.2）

- **第一次讀取用預設快取**：同一組截圖 5 分鐘內再讀，可能直接重播上次的回覆，不花用量。
- **「再讀一次」帶 `cache: false`**：讀錯了想重讀時，確定重新問。
- 解析失敗的回覆也可能被快取（C 4.2），所以「看不懂」之後的「再讀一次」一定帶 `cache: false`。

### 4.4 提示詞（定稿前可以給 GPT 審；不是頁面文字）

```
你會看到 {n} 張截圖，多半來自台灣「全民健保行動快易通｜健康存摺」的檢驗檢查結果或影像／病理報告，也可能是醫院的報告。請把截圖上看得到的檢查結果抄錄成 JSON。

規則：
- 只抄錄截圖上看得到的文字，照原文：不翻譯、不改寫、不換算單位、不補上截圖沒有的內容。英文報告照英文抄。
- 看不清楚、被截掉或被遮住的欄位填 null，並把欄位名稱放進這一項的 unclear。不要猜。
- 不要做任何判讀、評論、臨床判斷或建議。
- 不要自己判斷報告分類。只有截圖上寫出分類時（例如「BI-RADS 3」「Lung-RADS 2」「ATA low suspicion」），才把那段原文放進 class；沒有寫就填 null。
- 不要抄錄姓名、身分證號、病歷號、生日、電話、地址。報告全文裡出現時也略過。
- 每一個檢驗數值是一項 lab；每一份影像、內視鏡或病理報告是一項 report。
- date 是檢查或採檢日期，reportDate 是報告日期，照截圖上的寫法（民國或西元都照抄）。
- 數值旁邊的 H、L、↑、↓、* 等記號：和數值寫在一起就留在 value 裡；在獨立的一欄就放進 flag。
- report 的 exam 只能是下列代號之一，看不出是哪一種就填 null：
  breast_us 乳房超音波、breast_mammo 乳房X光攝影、breast_ct 乳房電腦斷層、thy_us 甲狀腺超音波、lung_ldct 低劑量胸部電腦斷層、gi_egd 胃鏡（上消化道內視鏡）、gi_colo 大腸鏡

只回一個 JSON 物件，不要其他文字：
{"items":[{"type":"lab","date":"115/10/20","reportDate":null,"place":"○○醫院","order":"甲狀腺刺激素","name":"TSH","value":"H 5.2","flag":null,"unit":"μIU/mL","ref":"0.27-4.20","unclear":[]},{"type":"report","date":"2026/10/20","reportDate":null,"place":"○○醫院","title":"Breast sonography","exam":"breast_us","class":"BI-RADS 3","text":"報告全文","unclear":["reportDate"]}]}
截圖上沒有任何檢查結果時，回 {"items":[]}。
```

- **繁體中文**：
  - 提示詞用繁體中文寫。
  - 回覆只有抄錄的原文、代號與 `null`，沒有模型自己寫的句子，所以英文報告保持英文。
- **提示詞不放任何家琳的資料**：只有截圖、張數、7 個檢查代號。
- **版本**：
  - 提示詞有版本號 `SHOT_PROMPT_VER`，存在每一筆的 `shot.promptVer`。
  - `d2`（審查後）：拿掉「同一個檢驗在兩張截圖重複出現時，只列一次」。這句沒有限定同日、同院、同值，模型可能在頁面看到之前就少列；重疊改由頁面依 3.7 判斷。
  - 改提示詞就換版本號。
- **解析 `parseShot(text, truncated)`**：
  - `truncated: true`：當作「內容太多」（4.5），不採用部分結果。
  - 先試整段 JSON，再試 Markdown code fence 裡的內容，再試第一個 `{` 到最後一個 `}`。
  - 有兩個以上 code fence 時算 `invalid`，不挑其中一個、也不合併（`sample.json` 的讀法也只接受一個 fence；審查 D-10）。
  - 檢查：
    - `items` 是陣列，最多 200 項。
    - 每一項的 `type` 是 `lab` 或 `report`。
    - 字串欄位不是字串的，當作 `null`。
    - `unclear` 不是陣列的，當作空陣列。
  - 不合規的單項略過，並在草稿清單上註明「有 2 項看不懂，已略過」。
  - 整份不合規時，算 `invalid`（4.5）。

### 4.5 錯誤處理（sample.d.ts 的 19 種，加上頁面自己的兩種）

- **共通規則**：
  - 所有錯誤都只顯示在面板的截圖區，不寫資料庫、不產生草稿。
  - 已經在確認中的草稿不受影響（不會因為再讀一次失敗而消失）。
  - 只依 `code` 分支。
  - 不認得的 code 當作 `upstream_error`。
  - 不自動重試。
- **處置分組同 C 4.4**：
  - 隱藏功能：`HIDE_CODES` 會讓「拍一餐」一起隱藏，因為 `sampleOff` 是共用的。
  - 可以原樣再試：給「再讀一次」。
  - 要改輸入：給「重新選截圖」。
  - 頁面程式的錯：只能手動填，這次不顯示選截圖（審查附帶項）。

| 錯誤碼 | 處置 | 顯示 |

| `upstream_error` | 可以原樣再試 | 「讀取中斷」＋「再讀一次」 |
| `cancelled`（按了停止） | 可以原樣再試 | 「已停止」＋「再讀一次」 |
| 頁面的 `invalid`（解析失敗、整份不合規） | 可以原樣再試 | 「讀取結果看不懂」＋「再讀一次」 |

- **讀到 0 項**（`{"items":[]}`）：不是錯誤，顯示「截圖裡沒有讀到檢查結果」＋「重新選截圖」。

  - 第一次呼叫時由平台跳出（C 1.1）。
  - 等待期間顯示「讀取中」，按「停止」照樣有效（sample.d.ts：等待同意時中止不花用量，視窗留著）。
  - 拒絕回 `not_granted`，處置如上表。

### 5.1 入口（`#dlgRec`，新增時）

[ 從截圖填入 ]

### 5.2 讀取中

- 區塊換成「讀取 2 張截圖中…」＋「停止」。
- 截圖很長時加一行提示（4.2）。
- 表單其他欄位照常可以手動填；讀完時：
  - 表單還沒動過：直接載入第一筆草稿。
  - 已經手動填了東西：不蓋掉，區塊顯示「讀出 2 筆」＋「開始確認」，按了才載入。
- **讀取中關掉面板**：
  - 讀取不中止。
  - 讀完時 toast「截圖讀好了，2 筆待確認」＋「繼續」。
  - 下次打開「新增檢查紀錄」，區塊顯示同樣的「繼續」（5.6）。

### 5.3 逐筆確認

- **草稿列**（表單最上方）：
  - 顯示「截圖 1/2・甲狀腺抽血・10/20」。
  - 右邊有「略過這筆」。
  - 有略過的單項時加一行（4.4）。
- **欄位**：
  - 這筆草稿的內容填進現有表單：檢查項目、日期、報告分類（5.4）、檢驗數值、報告內容、醫院。
  - 間隔與下次日期照現有規則算。
  - 抽血情境（服藥、生物素、變更後複查）不從截圖讀，照現有規則手動選。
- **每個從截圖填入的欄位**旁邊有小標「截圖」。下列情況改成提醒樣式，並在欄位下方寫原因：
  - 看不清楚：模型列在 `unclear`，值是空的。顯示「截圖看不清楚」。
  - 單位不同（3.3）、沒有單位。
  - 截圖裡有兩個不同的值（3.7）。
  - 只有報告日期、日期晚於今天（3.1）。
  - 報告內容已截斷（3.7）。
- **參考範圍與旗標**：每個檢驗欄位下方顯示一行小字，例如「參考 0.27–4.20・H・原文 H 5.2」。編輯時也照這樣顯示 `labMeta`。
- **儲存**：
  - 沿用現有的檢查（日期、間隔或指定日期）與寫入。
  - 多寫 `labMeta`、`shot`（第 2 節）。
  - 存好後 toast「已儲存 1/2」，自動載入下一筆，捲到表單最上方。
  - 最後一筆存好就關閉面板，toast「已儲存 2 筆」。
- **略過這筆**：
  - 不存，直接下一筆。
  - toast「已略過」＋「撤銷」：撤銷時回到那一筆，不需要 confirm。
- **存檔失敗**：照現有的 `writeErr`，停在這一筆，草稿不丟。

### 5.4 報告分類的確認

- 有建議的分類時（3.6）：
  - 「報告分類」預先選好建議值，欄位用提醒樣式。
  - 下方寫：「由截圖判讀，請確認：截圖寫『BI-RADS 3』」，並有「確認分類」按鈕。
  - 下次追蹤日期的預覽後面加「（分類待確認）」。
  - 儲存鈕停用，文字改成「先確認報告分類」。
- 按「確認分類」，或自己從選單改選任何一項（包括「未分類」），就算確認：
  - 提醒樣式拿掉。
  - 儲存鈕恢復。
- 沒有建議時（讀不出、有兩個以上、不建議的類別），選單維持「未分類」，不擋儲存。
  - 有提示文字時照 3.6 顯示，例如「截圖裡有不只一個分類（2、3），請自己選」。
- 分類只在使用者確認後才存；確認前離開這一筆（略過、關閉），什麼都不存。

### 5.5 可能重複

- 照 3.9，在日期欄下方顯示提醒樣式的一行。
- 不擋儲存。

### 5.6 沒確認完的草稿

- 草稿只在這次開啟的頁面記憶體裡，關掉頁面就沒了；它們本來就還沒存。
- 關掉面板時還有草稿：
  - 下次「新增檢查紀錄」的截圖區塊顯示「截圖讀出的紀錄還有 1 筆沒確認」＋「繼續」＋「丟棄」。
  - 丟棄用 toast 撤銷，不用 confirm。
- 有草稿時再選新截圖：新的草稿接在後面，不取代舊的。

### 5.7 點擊數

以 iOS 從「定期檢查」頁開始計。相簿的點擊是系統畫面，實際步驟要實機確認（第 7 節）。

| 情境 | 頁面上的點擊 | 相簿裡的點擊 | 合計 |
|---|---|---|---|
| 1 張截圖、1 筆抽血 | 新增檢查紀錄、從截圖填入、儲存（3） | 選 1 張、加入（2） | 5 |
| 2 張截圖、甲狀腺與生殖軸 2 筆 | 新增、從截圖填入、儲存、儲存（4） | 選 2 張、加入（3） | 7 |
| 1 份乳房超音波報告，有分類 | 新增、從截圖填入、確認分類、儲存（4） | 選 1 張、加入（2） | 6 |
| 讀錯一個值要改 | 每改一欄多 1–2 次（點欄位、輸入） | — | — |

- 這次開啟的頁面第一次呼叫時，多一次同意視窗（1–2 次點擊）。
- 等待時間另計：default tier 帶圖片時，第一段文字通常要 5–60 秒（sample.d.ts）。
- 對照手動輸入：新增、選項目、選日期、每個數值各點一次再打字，2 個數值大約 8 次以上，還要對著截圖逐字打。
- 每日記錄的「≤3 次點擊」標準針對早晚記錄（CLAUDE.md），不適用於檢查紀錄。

- 380 寬時不能水平捲動。

## 10. 決定（2026-11-01 使用者確認：D1–D4 全部照建議）

1. **D1 報告分類的範圍**：
   - 需求第 5 項說 Claude 可以建議分類；第 8 項說提示詞不做臨床判斷。

   - 這樣 BI-RADS、Lung-RADS 大多讀得到。
   - ATA 和大腸鏡在報告上通常不會直接寫成這裡的分類：
     - **甲狀腺**：寫出 ATA 高度、中度、低度懷疑時才建議。極低懷疑要看結節大小，只寫 TI-RADS 的不轉換。
     - **大腸鏡**：現有的分類要看息肉顆數、大小、病理類型，有時還要看清腸品質。這些常分在大腸鏡與病理兩份報告上，判斷屬於臨床判斷，所以一律不建議。報告全文照存，你自己選。

     - 這要另外處理病理報告與大腸鏡報告的配對、清腸品質、切除是否完整。
     - 規則與測試約多一倍。
   - **建議**：這次只做抄寫，大腸鏡不建議分類。
2. **D2 單位不同時**：
   - **建議**：欄位照填，值後面加截圖的單位（`15.4 pmol/L`），並標「未換算」。

   - 另一個做法：不填欄位，只寫進報告內容。欄位裡不會混單位，但趨勢表看不到這次的值。
   - 旗標與參考範圍只存在 `labMeta`。
