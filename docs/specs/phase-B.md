2026-10-30 擬定，依據 `docs/plan-phase-2-4.md` 的 B 節。狀態：**待 GPT 審查與使用者確認**，確認前不實作。

範圍：今天頁的服藥細節、「用藥」頁、劑量變更後的 TSH 複查日、甲狀腺抽血的抽血情境、「回診摘要」頁。全部只改頁面程式；臨床文字上頁前要查原文（第 5 節）。

## 1. 完成的定義

全部符合才算完成：

1. **今天頁服藥仍是一鍵**：沒記的時候點一下就記好，和現在一樣。已記錄時再點一下，展開服藥細節：服藥方式、干擾物、取消這筆紀錄。展開與填寫都是選填，不算進「完成」。
2. **「更多」新增「用藥」頁**：
   - 目前劑量
   - 服藥紀錄：近 30 天、90 天，寫成「27/30 天」這種中性的事實，不寫百分比，不做分數或連續天數。
   - 劑量變更與甲狀腺抽血結果，排在同一條時間軸上（直列）
   - 新增或編輯劑量變更
   - TSH 複查週數設定：沒有預設值，旁邊並列兩個依據
3. **TSH 複查日**：劑量變更後，依使用者設定的週數算出複查日，出現在今天頁的到期卡與用藥頁。沒設定週數就不排。之後有甲狀腺抽血的 TSH 結果，就視為已複查。
4. **甲狀腺抽血紀錄多兩個欄位**：抽血前是否已服藥、近一週是否吃過含生物素的保健品。兩個都是「是／否／不確定」，不填也能存。
5. **「更多」新增「回診摘要」頁**：選期間（預設是上次回診日到今天），產生摘要。可以複製文字，或存成 `.md`、`.html`。artifact 不能列印。
6. **向後相容**：
   - 舊資料都讀得到。沒有劑量變更紀錄時，用 `settings/profile.medDose`。
   - 匯出與匯入包含新的 `meddose` 集合；舊的備份檔照樣能匯入。
7. **測試**：新測試加進 `dev/test.sh`，全部通過，含 380px 深淺色的截圖、版面與對比檢查。
8. **臨床文字**：每一段都有原文出處，或標「待查證」不上頁（第 5 節）。

**不在這個階段**：
- 體重和 TSH 畫在同一張圖：會暗示兩者有因果關係（計畫書）。
- 服藥提醒的改動：A 階段已處理。
- 飲食：C 階段。
- 依 TSH 數值給建議，或自動判讀檢驗值。

## 2. 資料欄位（只新增，不改舊欄位的意義）

### 2.1 `days/{date}.med` 新增兩個選填欄位

```
med: { taken, at, dose,            // 原有
       mode: "fasting_am" | "bedtime" | "with_food" | "unsure",   // 新增，選填
       interfere: ["coffee","calcium","iron","ppi","soy","fiber"] 的子集合 }  // 新增，選填
```

- 舊紀錄沒有這兩個欄位：摘要寫「未填」，不推測。
- `mode` 的預設值見 9.1（沿用上次，或留空）。
- `dose`：記錄時取那一天的劑量（3.4 的 `doseOn(date)`），不再一律取目前設定。這修正了補登過去日子時用到目前劑量的問題。舊紀錄的 `dose` 不改。
- 寫入：照現有的 `writeDay` 合併寫入，只送改動的欄位，例如 `{med:{interfere:[...]}}`。陣列整個取代。

### 2.2 新集合 `meddose/{autoId}`

```
meddose/{id} { date: "YYYY-MM-DD",   // 生效日
               dose: 50,             // mcg，數字
               tablet: "100 mcg × ½",  // 選填，文字
               brand: "",            // 選填
               reason: "",           // 選填，例如「TSH 偏高」
               note: "",             // 選填
               recheckDue: null,     // 選填；只有使用者手動指定複查日時才存（見 3.4）
               createdAt, updatedAt, deleted: false }
```

- 刪除是軟刪除（`deleted: true`），附「撤銷」，和運動紀錄相同。
- 第一次使用不自動建立任何文件。沒有 `meddose` 時，時間軸最上面顯示「起始劑量 50 mcg（來自設定）」，而且沒有日期。

### 2.3 `settings/profile` 新增

- `tshRecheckWeeks`：數字或不存在。**沒有預設值，不可寫死**（計畫書、CLAUDE.md）。
- `lastVisit`：`"YYYY-MM-DD"` 或不存在。回診摘要的預設起點（9.3）。

### 2.4 `records/{id}.drawCtx`（只用在 `exam: "thy_lab"`）

```
drawCtx: { medBeforeDraw: true | false | null, biotin7d: true | false | null }
```

- `null` 或欄位不存在：未填。
- 其他檢查的紀錄不寫這個欄位。

### 2.5 匯出與匯入

- 匯出的集合加上 `meddose`；匯入時接受 `meddose`。
- 舊備份沒有 `meddose` 時照常匯入；預覽文字加上「劑量變更 n 筆」。

存取規則不變：`read: admin, write: admin`。不新增 capabilities：`downloads` 已經宣告。

## 3. 計算規則

放在 `src/index.html` 的標記區塊 `/* ---- med helpers: begin/end ---- */`，和 date helpers 一樣抽出來在 node 測試。

### 3.1 服藥紀錄（30／90 天）

- 範圍：今天往前 N 天，含今天。
- 不計入的日子：
  - 暫停期間（和頁面的 `isPaused` 相同）。
  - 開始記錄之前的日子：第一筆 `days` 文件之前不算，避免剛開始用就顯示「3/30」。
  - 今天還沒過完、而且還沒服藥：不算進分母。
- 顯示：「近 30 天：服藥 27/28 天（暫停 2 天不計）」。沒有可計的天數時寫「還沒有紀錄」。
- 不顯示百分比，不用紅綠，不做連續天數。

### 3.2 漏服日

在範圍內、不在暫停期間、沒有 `med` 的日子，列出日期（摘要使用）。

### 3.3 目前劑量與當日劑量

- 一筆紀錄算「有效」：`deleted` 不是 `true`，而且 `dose` 是數字。
- `doseOn(date)`：有效的 `meddose` 裡，`date ≤ 該日` 的最新一筆；同一天取 `createdAt` 最大的。沒有就用 `settings/profile.medDose`。
- 「目前劑量」= `doseOn(今天)`。生效日在未來的劑量變更，顯示為「預定 11/15 起 75 mcg」。

### 3.4 TSH 複查日

- 只看最新一筆有效的劑量變更，而且生效日 ≤ 今天。
- 複查日：
  - 有手動指定的 `recheckDue` → 用它。
  - 否則，有設定 `tshRecheckWeeks` → 生效日加週數 × 7 天。
  - 都沒有 → 不排。
- 已複查：有一筆甲狀腺抽血紀錄，日期 ≥ 生效日，而且 `labs.TSH` 有值。
- 顯示：
  - 今天頁到期卡：和現有檢查卡同樣的規則（60 天內、已逾期），名稱是「TSH 複查（劑量變更後）」。
  - 用藥頁：「TSH 複查：12/10（劑量變更後 6 週）」。
- 改了週數設定：沒有手動指定複查日的紀錄，會立刻依新週數重算。

### 3.5 回診摘要的內容

期間是 `from`～`to`（含頭尾）。各段都只寫事實，不加評論：

| 段落 | 內容 |
|---|---|
| 體重 | 早上 7 日平均：起點（`from` 前 7 天）、終點（`to` 前 7 天）、差值，寫成「+0.4 kg」，不用顏色；早上有量的天數 / 期間天數 |
| 服藥 | 服藥 a/b 天（同 3.1）；漏服日期；服藥方式分佈，含「未填」；干擾物各幾次 |
| 劑量變更 | 期間內每一筆：日期、劑量、錠劑規格、廠牌、原因 |
| 甲狀腺抽血 | 期間內每一筆：日期、TSH、Free T4（照原單位）、抽血前是否已服藥、近一週生物素 |
| 運動 | 每週平均分鐘（期間總分鐘 ÷ 週數） |
| 月經 | 標記的天數與日期區間 |
| 接下來的檢查 | `to` 之後 180 天內到期的檢查，含 TSH 複查；用頁面原有的到期算法 |

- 摘要文字由純函式 `summarize(data, from, to)` 產生 markdown；`.html` 是同一份內容的簡單 HTML，不連外部資源。
- 期間內沒有資料的段落，寫「期間內沒有紀錄」，不省略段落。

## 4. 畫面與互動

### 4.1 今天頁：服藥細節

- 沒記時：點一下記錄。和現在一樣，一次點擊，附「撤銷」。
- 已記錄時：點服藥列，在下方展開細節；再點一次收起。目前這一下只會顯示「取消這筆服藥紀錄」，改成展開以下內容：
  - **服藥方式**：四顆單選：早餐前空腹、睡前、隨餐、不確定。點了立刻存；再點同一顆就取消選擇。
  - **服藥前後有**：六顆複選：咖啡、鈣片、鐵劑、胃藥（PPI）、豆漿／大豆、高纖。每點一顆立刻存。
  - **取消這筆服藥紀錄**：沿用現有按鈕與「復原」。
- 不加說明文字。干擾物的間隔依據放在用藥頁的「依據」（第 5 節），查證後才上頁。
- 按鈕高度 ≥44px。展開區塊只出現在服藥列下方，上方元件不移動。
- 「完成」的定義不變。

### 4.2 「用藥」頁（更多 → 用藥）

由上到下：

1. **目前劑量**：「Levothyroxine 50 mcg」；副行是錠劑規格與服用方式，有就顯示；生效日在未來的劑量變更，顯示「預定 …」。
2. **服藥紀錄**：近 30 天、近 90 天兩行（3.1）。
3. **TSH 複查**：
   - 顯示複查日（3.4），或「劑量變更後的複查週數：未設定」。
   - 週數輸入框，留空就是不排。
   - 旁邊並列兩個依據（第 5 節第 5 項），查證後才上頁。
4. **時間軸**：劑量變更與甲狀腺抽血結果合在一起，依日期由新到舊直列。
   - 劑量變更：「11/01 劑量 50 → 75 mcg・100 mcg × ¾・原因」，點了可以編輯。
   - 抽血：「10/20 TSH 4.8・FT4 1.1・抽血前已服藥・生物素：否」，點了開啟原本的檢查紀錄表單。
   - 不畫成圖表：兩種數值單位不同，380px 寬放雙軸圖不清楚。
5. **新增劑量變更**按鈕：開啟底部表單。
   - 欄位：生效日（預設今天）、劑量 mcg、錠劑規格、廠牌、原因、備註、複查日（選填，覆蓋自動計算）。
   - 存檔後跳出 toast，附「撤銷」。編輯時可以刪除（軟刪除，附撤銷）。
6. **依據**（摺疊）：第 5 節查證過的內容與出處。

### 4.3 甲狀腺抽血表單

- 只有選「甲狀腺抽血」時才出現：
  - 「抽血前已服藥」：是／否／不確定
  - 「近一週吃過含生物素的保健品」：是／否／不確定
- 用現有的 `.seg` 按鈕組。預設不選，存成 `null`。
- 編輯舊紀錄時，沒有 `drawCtx` 就顯示未選。

### 4.4 「回診摘要」頁（更多 → 回診摘要）

- 期間：兩個日期欄位。
  - 預設是 `lastVisit` 到今天；沒有 `lastVisit` 時，預設今天往前 90 天。
  - 改了日期，預覽立刻更新。
- 預覽：摘要內容（3.5），用頁面樣式顯示。
- 按鈕：
  - **複製文字**：用 `navigator.clipboard.writeText`。失敗時（artifact 的 iframe 可能不允許），把文字放進唯讀文字框並全選，toast「已選取，請長按複製」。
  - **存成 .md**、**存成 .html**：用 `downloads` 能力，檔名「家琳回診摘要-YYYYMMDD-YYYYMMDD」。
  - **把結束日設為這次回診日**：寫入 `lastVisit = to`，附「撤銷」。
- 不加列印按鈕（不能 `window.print()`）。

### 4.5 設定頁的劑量欄位

見 9.2。

### 4.6 主題與版面

- 顏色全部用 `:root` token，不新增顏色。
- 380px 寬沒有水平捲動；淺色、深色都要通過 `dev/a11y.js`。
- 新頁面沿用子頁的樣式（`.sect`、`.blk`、`.grp`、`.kv`）。

## 9. 待決定（請在確認時回覆）

1. **服藥方式的預設**：計畫書寫「預設沿用上次」，也就是記錄服藥時自動帶入上次的方式。

   - **建議：不自動帶入，留空（摘要寫「未填」）**；展開細節時，把上次的方式顯示成淡色提示，點一下就套用。這樣每次記錄仍是一次點擊，資料也不會被推測。
