## 1. 完成的定義

全部符合才算完成：

1. **每次記錄的點擊數不變**：
   - 早上：體重開啟、儲存，加上服藥，共 3 次點擊。
   - 晚上：體重開啟、撥尺確認、儲存，共 3 次點擊。今天已有早上體重時，晚上的預設是估計值，要先撥尺確認才能存（CLAUDE.md），和現在相同。
   - 和現在相同，有測試驗收。服藥細節是另外的選填動作，不算進這兩個流程，也不算進「完成」。
2. **服藥細節**：已記錄時，點服藥列會展開，可以填服藥方式、自行標記的相關攝取，或取消這筆紀錄。網路回應與重繪不會收起展開的區塊，也不會移動上方元件。
3. **「更多」新增「用藥」頁**：
   - 目前劑量
   - 服藥紀錄：「已記錄服藥 a/b 天」
   - TSH 複查狀態
   - 劑量、製劑變更與甲狀腺抽血結果排在同一條直列時間軸上
   - 新增或編輯變更
4. **TSH 複查**：
   - 劑量或製劑變更後，依使用者設定的週數（或手動指定的日期）排出複查日。沒設定就不排。
   - 抽血紀錄要明確連結到這次變更，才算完成複查。
   - 複查日出現在今天頁的到期卡與用藥頁。
5. **甲狀腺抽血**：多兩個情境欄位：抽血前是否已服藥、近一週是否吃過含生物素的保健品。四種狀態：是、否、不確定、未填。
6. **「更多」新增「回診摘要」頁**：選期間，可以複製文字，或存成 `.md`、`.html`。每一段的邊界依 3.6。
7. **向後相容**：
   - 舊資料都讀得到，舊的 `med` 紀錄、檢查紀錄不需要遷移。
   - 匯出與匯入包含 `meddose`。匯入的語意不變：相同編號的紀錄會被備份內容覆蓋（2.5）。
8. **測試**：新測試加進 `dev/test.sh`，全部通過，含 380px 深淺色的截圖、版面與對比檢查。
9. **臨床文字**：每一段上頁的文字都有原文出處；查不到或原文不支持的，不上頁（第 5 節）。

**不在這個階段**：
- 體重和 TSH 畫在同一張圖。
- 依 TSH 數值給建議，或自動判讀檢驗值。
- 停藥：劑量 0 不支援。
- 暫停的歷史紀錄（3.1）。
- 版本化的合併匯入（2.5）。
- 飲食。

## 2. 資料欄位（只新增，不改舊欄位的意義）

### 2.1 `days/{date}.med`

```
med: { taken: true, at, dose,                          // 原有
       doseSrc: "history" | "setting",                 // 新增：記錄時的劑量來自劑量紀錄，或依設定推定
       mode: "fasting_am" | "bedtime" | "with_food" | "unsure" | null,   // 新增，選填；null 或不存在 = 未填
       interfere: { coffee, calcium, iron, ppi, soy, fiber } }          // 新增，選填；每項 true = 有標記、false = 標記否、不存在 = 未填
```

- **服藥成立的條件統一為 `med.taken === true`**（審查第 2 點）。
  - 舊紀錄一律是頁面寫的 `{taken:true, at, dose}`，所以結果不變。
  - 只有細節、沒有 `taken` 的物件（例如另一台裝置已取消，舊畫面又送出細節）不算服藥。
  - 頁面的 `needed()`、週圓點、服藥列都改用這個條件。A 階段的提示詞與參考實作也要同步（7 的 B6）。
- **細節的寫入**：
  - 只在本機看到 `med.taken === true` 時才送出；否則 toast「這筆服藥紀錄已取消」，不寫入。
  - 每次只送一個 key，例如 `{med:{interfere:{coffee:true}}}` 或 `{med:{mode:"bedtime"}}`，靠巢狀合併寫入。干擾物改成物件而不是陣列：連點兩項、或兩台裝置各點一項，都不會互相覆蓋（審查第 3 點）。
  - 本機連點時，畫面用待寫入的值顯示，寫入照順序排隊（和 A 階段開關的做法相同）。
- **取消後「復原」**：寫回取消前的整個 `med`。如果取消到復原之間，另一台裝置改過細節，復原會蓋掉那次改動。這是已知限制，因為兩台裝置同時編輯同一天細節的情況很少。
- **`dose` 與 `doseSrc`**：記錄時寫入當日劑量 `doseOn(date)` 與它的來源（3.3）。既有紀錄的 `dose` 快照不改。回診摘要的劑量段會列出這些快照（3.6）：`doseSrc` 是 `setting` 的標「記錄時依設定推定」；舊紀錄沒有 `doseSrc`，照快照列出、不加註。

### 2.2 新集合 `meddose/{autoId}`

```
meddose/{id} { kind: "dose" | "product",   // 劑量變更，或只換廠牌／製劑（審查補充、ATA 3d）
               date: "YYYY-MM-DD",         // 生效日，可以是未來
               dose: 50,                   // mcg；有限數字，1–1000；product 時填當時劑量
               tablet: "", brand: "", reason: "", note: "",   // 選填文字
               recheckDue: null,           // 選填：手動指定的複查日
               noRecheck: false,           // 選填：這筆不需要複查（例如只是補記舊資料）
               createdAt, updatedAt, deleted: false }
```

- **有效紀錄**：`deleted` 不是 `true`、`date` 是合法日期、`dose` 是 1–1000 的有限數字。無效紀錄不參與計算；時間軸照樣列出，標「資料不完整」。
- **排序**：依 `date`、`createdAt`、文件 id 排列，不會有不確定的順序。同一天有多筆時，只有排最後的那筆生效；其他筆在時間軸上標「同日較早的紀錄」。
- **刪除**：軟刪除，附「撤銷」。
- **第一次使用**：不自動建立任何文件。

### 2.3 `settings/profile` 新增

- `tshRecheckWeeks`：1–52 的整數，或不存在。**沒有預設值，不可寫死**；也不套用 CLAUDE.md「取下限」的一般規則（審查臨床第 5 項）。
- `lastVisit`：`"YYYY-MM-DD"` 或不存在。只有使用者在摘要頁明確按下才會寫入，可撤銷；產生或下載摘要都不會自動更新它（9.3）。

### 2.4 `records/{id}.drawCtx`（只用在 `exam: "thy_lab"`）

```
drawCtx: { medBeforeDraw: "yes" | "no" | "unsure",   // 不存在 = 未填
           biotin7d:      "yes" | "no" | "unsure",
           recheckOf:     "<meddose id>" }            // 這筆抽血是哪一次變更後的複查；不存在 = 不是
```

- 用字串表示四種狀態（審查第 8 點）。舊紀錄沒有這個欄位，就是未填，不需要遷移。
- 切換到其他檢查種類時，表單不保留也不寫入 `drawCtx`。

### 2.5 匯出與匯入

- 匯出的集合加上 `meddose`，匯入時接受 `meddose`。
- **匯入的語意不變**（審查第 4 點只部分採納）：
  - 相同編號的紀錄，會被備份內容整份覆蓋。
  - 備份裡沒有的紀錄保留。
  - 這是「還原」，不是合併。
- 預覽多三件事：
  - 列出劑量變更的筆數。
  - 備份裡沒有 `meddose`，或日紀錄沒有 B 階段的欄位時，加一句警告：「這份備份比 B 階段舊；相同日期的服藥細節、抽血情境會被備份內容取代。建議先匯出目前的資料。」
  - 舊備份可能讓已刪除的劑量變更重新出現（備份裡它還沒被刪），預覽也寫明這一點。
- 不做版本化合併、不自動先備份（下載需要使用者操作）。
- 部分失敗沿用現有的計數與提示。
- 匯出不包含 `system/heartbeat`（和現在相同）。

存取規則不變：`read: admin, write: admin`。不新增 capabilities。

## 3. 計算規則

放在 `src/index.html` 的標記區塊 `/* ---- med helpers: begin/end ---- */`。全部是純函式：今天的日期、設定、資料都從參數傳入，不讀全域狀態；抽出來在 node 測試。

### 3.0 載入

- `meddose` 的伺服器快照到達之前，不能記錄服藥（審查第 5 點）。
  - 頁面的 `ready` 改成同時等 `days`、`profile`、`meddose`。
  - 監聽失敗時，沿用全頁的「資料連線中斷」。
- 有三種狀態：尚未載入、載入失敗、確實沒有紀錄。只有「確實沒有紀錄」時，才顯示「沒有劑量紀錄」或摘要的「期間內沒有紀錄」。
- 回診摘要要等 `days`、`exercise`、`records`、`meddose`、`profile`、`intervals` 都載入，才產生內容。

### 3.1 服藥紀錄的可計日

用於用藥頁的 30／90 天，也用於摘要。

- **追蹤起點**：最早一個有 `am`、`pm` 或 `med.taken` 的日期。只有月經標記、或空的文件，不算起點（審查第 10 點）。
- **可計日**：範圍內、不早於起點、不在暫停期間，而且不是「今天但還沒服藥」。
- **分子**：可計日裡 `med.taken === true` 的天數。
- **未記錄日期**：可計日扣掉分子的那些日子。
- **暫停日**：分子、分母都不算；暫停期間有服藥紀錄，也不計入。
- 顯示：「近 30 天：已記錄服藥 27/28 天（暫停 2 天不計）」。可計日是 0 時寫「還沒有紀錄」。
- 用詞是「已記錄服藥」與「未記錄的日子」，不寫「漏服」：沒有紀錄不等於沒有吃（審查第 9 點）。
- **已知限制**：暫停只看目前設定的那一段。清除或改設暫停後，過去的統計會跟著變。用藥頁的「依據」區塊註明這一點。

### 3.2 範圍

- 「近 N 天」是今天往前 N−1 天到今天，共 N 天。

### 3.3 當日劑量 `doseOn(date)`

- 有效紀錄裡，`date ≤ 該日`、排序最後的那一筆 → `{dose, src:"history", id}`。
- 沒有 → `settings/profile.medDose` 是 1–1000 的有限數字時，`{dose, src:"setting"}`，顯示「依設定推定」。
- 都沒有 → `null`，顯示「劑量未設定」；記錄服藥時 `dose` 存 `null`。
- 所有有效紀錄都刪掉之後，回到依設定推定；只有未來的紀錄時，生效日之前也是依設定推定。
- 今天頁服藥列顯示的劑量、記錄時寫入的劑量，都用 `doseOn(viewDate)`（審查第 6 點）。補登過去的日子，也用那一天的劑量。

### 3.4 TSH 複查（審查第 1、12 點）

- **對象**：有效紀錄裡，`date ≤ 今天`、排序最後的那一筆。未來的變更不算。
- **狀態**（依序判斷）：
  1. `none`：沒有對象，或對象的 `noRecheck` 是 `true`。
  2. `done`：有一筆甲狀腺抽血紀錄同時符合：
     - `drawCtx.recheckOf` 是對象的 id
     - 採檢日晚於對象的生效日（同一天的基準抽血不算），而且 ≤ 今天
     - `labs.TSH` 的文字裡至少有一個數字（`"<0.01"`、`"0"` 算；空白、「待報」不算）
     
     這筆抽血被刪除或改掉時，狀態會重新計算。
  3. `manual`：對象有合法的 `recheckDue` → 複查日就是它，顯示「手動指定」。
  4. `auto`：設定了 `tshRecheckWeeks` → 生效日加週數 × 7 天，顯示「生效後 N 週」。
  5. `unset`：都沒有，顯示「複查週數未設定」，不排。
- **為什麼要明確連結**：自動用日期判斷，會把「決定調藥的那次抽血」或「太早的抽血」當成複查完成；寫死一個日期窗口，又等於替醫師決定時機。所以由抽血表單的切換鍵明確連結，預設值見 4.3。
- **今天頁到期卡**：
  - `manual`、`auto` 狀態，套用現有規則（60 天內、已逾期），名稱是「TSH 複查（劑量變更後）」。
  - 例行的甲狀腺抽血照舊另外排，兩項可能同時出現，卡片寫「另有 n 項」。
  - 點卡片：最優先的是 TSH 複查時，到「用藥」頁；其他照舊到「定期檢查」（審查第 13 點）。
- 例行抽血的到期日照舊，從最新一筆甲狀腺抽血紀錄算起。完成複查的那次抽血也是一筆甲狀腺抽血紀錄，所以會自動更新例行到期日，不會重複催。

### 3.5 檢驗值

- `labs` 存的是使用者輸入的原文，鍵名沿用 `TSH`、`Free T4`。
- 摘要照原文顯示，不轉成數字、不換算單位。
- 單位只能寫「依表單欄位：TSH μIU/mL、Free T4 ng/dL」，不宣稱已核對原報告（審查第 7 點）。沒有新增逐筆的單位欄位。

### 3.6 回診摘要 `summarize(snapshot, from, to, today, settings)`

- **期間**：
  - 必須 `from ≤ to ≤ today`，不合法時不產生，並提示原因。
  - 預設：`lastVisit` 合法而且 ≤ 今天時，從 `lastVisit` 到今天；否則從今天往前 89 天到今天。
- **基準日**是 `to`。只看日期 ≤ `to` 的資料，不用之後的紀錄抵銷當時的待辦。
- 各段內容如下，期間內沒有資料就寫「期間內沒有紀錄」，不省略段落：

| 段落 | 規則 |
|---|---|
| 體重 | 起點窗 `[from, from+6]`、終點窗 `[to−6, to]`，各算早上體重的平均，每個窗至少要 3 筆；寫出兩個平均、各自的筆數、差值（例如「+0.4 kg」，不用顏色）。期間少於 14 天時兩窗重疊，就不算差值，只寫期間平均（至少 3 筆）。另寫「早上有量 n／期間 d 天」 |
| 服藥 | 用 3.1 的可計日（範圍換成 `[from, to]`）：「已記錄服藥 a/b 天」，列出未記錄的日期。服藥方式：只算 `taken` 的日子，分成早餐前空腹、睡前、隨餐、不確定、未填。自行標記：每一項寫標記為「有」的天數，例如「咖啡 3 天」；不寫成已證實的干擾 |
| 劑量 | 三行，依序：(1)「服藥紀錄上的劑量」：期間內 `taken` 日子的 `med.dose` 快照，依劑量分組，寫天數與日期範圍；`doseSrc` 是 `setting` 的另成一組並標「記錄時依設定推定」；`dose` 無效的寫「劑量沒有記錄 n 天」；沒有服藥紀錄就寫「期間內沒有服藥紀錄」。(2)「期初的劑量紀錄」：`doseOn(from)` 來自劑量變更紀錄時寫劑量；沒有紀錄時寫「沒有」，並在括號寫「依目前設定推定 X mcg」，不和快照混在一起。(3) 期間內每一筆有效變更（日期、類型、劑量、錠劑規格、廠牌、原因），同日較早的紀錄不列（審查第 2 點） |
| 甲狀腺抽血 | 期間內每一筆，依採檢日排序：TSH、Free T4（原文，缺的寫「未填」，不省略整筆）、抽血前服藥、近一週生物素（是／否／不確定／未填）、是否為變更後的複查 |
| 運動 | 只算有效紀錄：未刪除、分鐘是正的有限數字。期間天數 d ≥ 7 時寫「每週平均 X 分（共 Y 分）」，X = Y ÷ (d/7) 四捨五入；d < 7 時只寫總分鐘 |
| 月經 | 實際標記的日期合併成連續區段，不跨過沒有標記的日子；區段碰到期間邊界時，加註「期間外可能還有」 |
| 待辦與接下來的檢查 | (a) 截至 `to` 仍待處理：已逾期、待安排，以及到期而未完成的 TSH 複查；(b) `to` 之後 180 天內到期的。檢查的到期算法沿用頁面的 `dueOf`，TSH 複查沿用 3.4，基準日都換成 `to` |

- **輸出與安全**（審查第 16 點）：
  - 預覽、複製、`.md`、`.html` 都從同一份資料快照產生。
  - 自由文字（廠牌、原因、備註、檢驗值）要先跳脫：
    - HTML：跳脫 `& < > " '`。
    - Markdown：跳脫 `\ * _ [ ] ( ) < > ! # \``。
  - 不產生連結或圖片，不連外部資源。
  - 下載被拒或失敗時，顯示失敗，不顯示「已存」。

## 4. 畫面與互動

### 4.1 今天頁：服藥細節

- 沒記時：點一下記錄，和現在一樣，附「撤銷」。
- 已記錄時：點服藥列展開細節，再點一次收起。目前這一下只會顯示「取消這筆服藥紀錄」，改成展開以下內容：
  - **服藥方式**：早餐前空腹、睡前、隨餐、不確定，四顆單選。點了立刻存；再點同一顆就是未填。
    - 不自動沿用上次（9.1）。還沒填時，上次用的那一顆加上虛線框和「・上次」，點一下就套用。不另外加按鈕，避免同一個選項出現兩次。
  - **自行標記（服藥前後）**：咖啡、鈣片、鐵劑、胃藥（PPI）、豆漿／大豆、高纖，六顆。
    - 點一下標記「有」（寫入 `true`）；再點一下取消（寫入 `false`，畫面上和沒點過一樣）。
    - 沒點過的項目不寫入，就是未填。
    - 摘要只算標記「有」的天數。
    - 名稱用「自行標記」，不寫「干擾物」（審查第 15 點）。
  - **取消這筆服藥紀錄**：沿用現有按鈕與「復原」。
- 不加說明文字。各項的依據放在用藥頁的「依據」區塊，查證後才上頁。
- 按鈕 ≥44px。展開區塊在服藥列下方，上方元件不移動。重繪時保持展開狀態。

### 4.2 「用藥」頁（更多 → 用藥）

由上到下：

1. **目前劑量**：
   - 「Levothyroxine 50 mcg」。依設定推定時，加上「（依設定推定）」。
   - 副行：錠劑規格、服用方式。
   - 有未來生效的變更時，加一行「預定 11/15 起 75 mcg」。
2. **服藥紀錄**：近 30 天、近 90 天兩行（3.1）。
3. **TSH 複查**：
   - 狀態（3.4）：複查日加上「手動指定」或「生效後 N 週」、「已完成（11/20 抽血）」、「複查週數未設定」。
   - 週數輸入框：1–52 的整數，留空就是不排。
   - 旁邊並列兩個依據（第 5 節第 5 項），查證後才上頁。
4. **時間軸**：劑量、製劑變更與甲狀腺抽血，依日期由新到舊直列。
   - 變更：「11/01 劑量 50 → 75 mcg・錠劑規格・原因」或「11/01 換製劑・廠牌」。點了可以編輯。
   - 抽血：「10/20 TSH 4.8・Free T4 1.1・抽血前已服藥・生物素：否・複查」。點了開啟原本的檢查紀錄表單。
   - 同日較早的紀錄、資料不完整的紀錄要加註。
   - 不畫圖表。
5. **新增變更**按鈕：開啟底部表單。
   - 欄位：類型（劑量變更／換廠牌或製劑）、生效日（預設今天）、劑量 mcg（必填，1–1000）、錠劑規格（placeholder「例如 100 mcg × ½」，只是輸入範例，不是建議）、廠牌、原因、備註、複查日（選填，會蓋掉自動計算）、「這筆不需要複查」。
   - 驗證失敗時，指出是哪一個欄位，不存。
   - 存檔後跳出 toast，附「撤銷」。編輯時可以刪除（軟刪除，附撤銷）。
6. **依據**（摺疊）：第 5 節查證過的內容與出處，加上 3.1 的暫停限制。

### 4.3 甲狀腺抽血表單

只有選「甲狀腺抽血」時才出現：

- **抽血前已服藥**：是、否、不確定，三選一；再點已選的那一顆就回到未填。
- **近一週吃過含生物素的保健品**：同上。
- **這次是 11/01 變更後的複查**：切換鍵，在以下情況出現：
  - 複查對象存在，狀態不是 `none`；
  - 或這筆紀錄原本就已經連結。
  
  預設值：
  - 新紀錄的採檢日晚於生效日，而且 ≤ 今天 → 預設開；
  - 同日、較早或未來的日期 → 預設關，切換鍵停用並註明原因。
  
  存成 `drawCtx.recheckOf`。要撤回，就編輯或刪除這筆紀錄（現有的刪除附撤銷）。

其他規則：
- 編輯舊紀錄時，沒有 `drawCtx` 就全部顯示未填。
- 存檔時保留紀錄裡表單沒有顯示的欄位。
- 遠端快照不打斷正在輸入的表單（沿用現有的 `typingIn` 規則）。

### 4.4 「回診摘要」頁（更多 → 回診摘要）

- **預覽**：照 3.6 的內容；資料還沒載入時，顯示「資料載入中」。
- **按鈕**：
  - **複製文字**：用 `navigator.clipboard.writeText`。失敗時，把文字放進唯讀文字框並全選，toast「已選取，請長按複製」。
  - **存成 .md**、**存成 .html**：用 `downloads` 能力，檔名「家琳回診摘要-YYYYMMDD-YYYYMMDD」。沒有這個能力、使用者拒絕或失敗時，顯示對應的訊息。
  - **把結束日設為這次回診日**：寫入 `lastVisit = to`，附「撤銷」。
