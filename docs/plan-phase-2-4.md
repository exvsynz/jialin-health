# 第 2–4 階段計畫：提醒、用藥與回診摘要、飲食照片

2026-10-30 擬定。實作由 Claude Code 負責，GPT 做獨立審查。只有 claude.ai 那邊的 Claude 能做的事，另外標出來。

## 分工

| 誰 | 做什麼 |
|---|---|
| Claude Code | 寫規格、實作、測試（沿用 `dev/`）、在分支上 commit、合併 `main` |
| GPT | 每階段兩次獨立審查：動手前審規格，合併前審程式與臨床文字。報告存 `docs/reviews/` |
| claude.ai 的 Claude | 只有它能做的事：發布到原網址、變更 capabilities、建立或修改排程任務、讀寫正式資料庫做功能檢查 |
| 使用者 | 每個關卡做決定、手機實測、決定臨床預設值 |

## 建議順序：A 提醒 → B 用藥與回診摘要 → C 飲食照片

- **A 先做**：每日紀錄能不能撐下去，主要看有沒有提醒。A 的程式量最少，排程讀寫資料庫也已經實測成功（2026-10-30，`system/heartbeat`）。
- **B 其次**：這是 artifact 相對於現成 App 最獨特的價值，而且只需要頁面程式。
- **C 最後**：要新增「頁面呼叫 Claude 看圖」的能力，風險和不確定性最高。兩份規劃審查也都建議放最後。

順序可以調，三個階段彼此獨立。

## 每個階段的流程

1. Claude Code 寫規格（`docs/specs/phase-X.md`）。
2. GPT 審規格。
3. 使用者確認。
4. Claude Code 實作，在分支上 commit，跑 `dev/test.sh`。
5. GPT 審程式與臨床文字。
6. 修正後合併 `main`。
7. 回到 claude.ai 說「發布最新版」。
8. 手機實測一週。

## 共通規則

- 資料模型只新增欄位或集合，不改舊欄位的意義。舊資料一定要讀得到。
- 新的臨床文字上頁前，要查原始來源並標出處。查不到就標「待查證」，不放上頁面。
- 今天畫面維持 `CLAUDE.md` 的設計原則：每次記錄 ≤3 次點擊；新功能不列入「完成」，除非使用者決定要列入。
- `dev/mock-claude.js` 要隨新能力擴充，例如 `sample`，所有流程都要能在本機測。

## A：提醒

**完成的定義**
- 每天兩個排程任務，時間在 07:2x 和 22:2x（台北時間）。有缺漏才推播，全部記錄了就不推播。
- 每次執行都寫一筆心跳。頁面顯示「上次檢查」時間；超過 26 小時沒有心跳，就顯示「提醒可能停了」。
- 每週日一次週報，內容：
  - 7 日平均體重
  - 本週服藥天數
  - 運動分鐘
  - 30 天內到期的檢查
  - 距上次匯出超過 30 天時提醒備份
- 暫停模式期間不提醒。
- 實測一週，誤報 ≤1 次。

**資料**（只新增）
- `system/heartbeat`：`{ at, kind: "morning"|"evening"|"weekly", missing: [], paused, ok }`
- `settings/profile.remind`：`{ morning: true, evening: true, food: false, weekly: true }`。開關放在設定頁，排程任務照這些開關決定要不要提醒。

**檢查規則**（排程任務的提示詞照這裡寫）
- 日期依台北時間，凌晨 4 點前算前一天。這兩個時段都不會碰到換日。
- 早上：缺早上體重或缺服藥，就提醒。
- 晚上：
  - 缺晚上體重或缺服藥，就提醒。
  - `remind.food` 開啟且今天沒有飲食紀錄時，也提醒（C 完成後才用得到）。
  - 7 天內有到期的檢查時，順帶一行。
- 推播文字只寫一行，例如「家琳今天還沒記：晚上體重、服藥」。

**分工**
- Claude Code：
  - 設定頁的提醒區塊（開關、心跳狀態）
  - 三份排程提示詞，放在 `ops/scheduled/morning.md`、`evening.md`、`weekly.md`
  - mock 測試
- claude.ai：
  - 照 `ops/scheduled/` 建立三個排程任務
  - 先建一次性測試，確認兩件事：「有缺」時會推播、「無缺」時不會推播（推播是否只在「值得注意」時送出，還沒實測過）
  - 回報每次執行需不需要核准

**成本**：每月約 60 次每日檢查加 4 次週報，每次都是一個新的工作階段。

## B：用藥細節與回診摘要

**完成的定義**
- 今天頁服藥仍是一鍵。記錄後可以展開，補服藥方式和干擾物。
- 「更多」新增「用藥」頁：
  - 目前劑量
  - 劑量變更時間軸，TSH 和 FT4 數值標在同一條時間軸上
  - 30 天和 90 天服藥率，用中性方式呈現
  - 新增劑量變更
- 劑量變更後，依使用者設定的週數排出 TSH 複查日，出現在今天頁的到期卡。沒設定週數就不排。
- 甲狀腺抽血紀錄多兩個勾選：抽血前是否已服藥、近一週是否吃過含生物素的保健品。
- 新增「回診摘要」頁：選期間（預設是上次回診到今天），可以複製文字或存成 `.md`／`.html`。artifact 不能列印。

**資料**（只新增）
- `days/{date}.med` 加選填欄位：
  - `mode`：`"fasting_am"|"bedtime"|"with_food"|"unsure"`，預設沿用上次
  - `interfere`：`["coffee","calcium","iron","ppi","soy","fiber"]` 的子集合
- 新集合 `meddose/{id}`：`{ date, dose, tablet, brand, reason, note, recheckDue }`。`tablet` 例如「100 mcg × ½」。
- `settings/profile.tshRecheckWeeks`：由使用者填。沒有預設值，不可寫死。
- `records/{id}.drawCtx`（只用於甲狀腺抽血）：`{ medBeforeDraw: true|false|null, biotin7d: true|false|null }`

**回診摘要內容**
- 體重：7 日平均的起點、終點與變化；早上有量的天數
- 服藥：服藥率、漏服的日期、服藥方式分佈、干擾物次數
- 劑量變更
- TSH、FT4 列表，附抽血情境
- 運動每週平均分鐘
- 月經標記天數
- 接下來要做的檢查

**臨床內容，上頁前要查原文**

以下是 2026-10-30 規劃審查整理的資料，這個工作階段沒有逐一核對原文。

1. 服藥時機：早餐前 60 分鐘，或睡前且晚餐後 3 小時以上（ATA 2014；Jonklaas et al., *Thyroid* 2014;24:1670）
2. 與鈣、鐵、制酸劑等的間隔（ATA 2014）
3. 咖啡對吸收的影響（Benvenga et al., *Thyroid* 2008）
4. 生物素對免疫分析的干擾（Li et al., *JAMA* 2017；FDA 安全通訊 2017、2019）
5. 劑量變更後多久複查 TSH：FDA 藥品說明書寫 6–8 週，ATA 寫 4–6 週，兩者不同。頁面只呈現依據，預設值由使用者決定。
6. 服藥後幾小時內抽血，FT4 可能暫時偏高（ATA 2014 引用的資料）

**不要做**
- 體重和 TSH 不畫在同一張圖，會暗示兩者有因果關係。
- 服藥率不做成分數或連續天數。

## C：飲食照片

**完成的定義**
- 今天頁新增「拍一餐」：點按鈕、拍照，兩次點擊完成。照片自動壓縮並估算。
- 只存約 320px 的縮圖（≤40 KB，以 data URI 存在文件內），不存原圖，所以不需要 `assets` 能力。
- 估算結果是範圍，例如「約 450–650 kcal」，附信心程度。可以補一句份量（例如半碗、有湯）後重新估算，也可以手動改數字。
- 飲食頁顯示每餐縮圖與當日總熱量範圍。今天頁只顯示「今天 2 餐」，不顯示熱量。
- 不設熱量目標，不用紅綠，不列入「完成」。
- 驗收：使用者用自己秤過的 10 餐對照，記錄真值有沒有落在範圍內。落入率低於 70% 就調整提示詞或放寬範圍。

**資料**（只新增）
- `meals/{id}`：`{ date, at, meal: "早餐"|"午餐"|"晚餐"|"點心", thumb, desc, items: [{name, portion}], kcalLo, kcalHi, confidence: "低"|"中"|"高", note, edited, est: { at, modelTierApplied }, deleted }`
- `meal` 依時間預設，可以改。
- 每筆文件上限 256 KiB；整個資料庫上限 25,000 筆，每天 4 餐大約可用 17 年。

**頁面呼叫 Claude 的用法**（runtime contract 0.2.92，`sample` 能力）
- 發布時要宣告 `capabilities: { sample: { images: true } }`。這步由 claude.ai 做，Claude Code 只寫程式。
- 先檢查 `await (await claude.use("sample"))?.limits()`，結果裡有 `images` 才顯示「拍一餐」，並用 `images.mediaTypes` 設定 `accept`。
- 呼叫方式：`await sample.json(提示詞, { images: jpegBlob })`。圖片放在 `images`，不放在文字裡。
- 只能在使用者動作之後呼叫。第一次呼叫會跳同意視窗。
- 同樣的輸入在 5 分鐘內會直接回快取。
- 要處理的錯誤碼：
  - `not_granted`、`images_unavailable`：隱藏「拍一餐」功能
  - `rate_limited`：稍後再試
  - `image_rejected`：圖檔有問題
  - `empty_completion`、JSON 解析失敗：顯示「再估一次」
- 拍照：`<input type="file" accept="image/*" capture="environment">`。用 canvas 縮成兩個版本：長邊 1280 的 JPEG 送去估算，320 的縮圖存起來。
- 估算進行中先建立文件，狀態標「估算中」，所以估算失敗也不會遺失照片紀錄。

**提示詞要求**
- 說明這是台灣常見餐點。
- 輸出固定 JSON：`items`、`kcalLo`、`kcalHi`、`confidence`、`desc`。
- 看不清楚時放寬範圍並標低信心。
- 不給飲食建議或評論。

**分工**
- Claude Code：上述全部程式、mock 的 `sample`、測試。
- claude.ai：發布時加上 `sample: { images: true }`；在正式頁面確認 `limits().images` 存在；回報實際的大小與張數限制。
